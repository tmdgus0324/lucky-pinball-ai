이 장은 README에 없는 장이라 처음부터 AI가 정리했습니다. JSP에 익숙한 사람이 React 화면 전체를 어떻게 구성하는지 감을 잡도록, 같은 게시판을 세 단계로 옮겨 봅니다. 코드 탭은 `main.jsp` → `BoardMain.jsx` → `BoardPage.jsx` 순서로 보면 됩니다.

```
1단계  main.jsp            위에 <script>, 아래에 <body>. 익숙한 방식
2단계  BoardMain.jsx       React 한 파일. main.jsp와 같은 배치(위에 state와 함수, 아래에 화면)
3단계  BoardPage.jsx 외    화면 조각(컴포넌트)과 훅으로 나눈 모양. 실무 React 코드는 대부분 이 모양
```

## 1. 화면을 그리는 곳이 다르다

```
JSP
  브라우저 ── /board/main.do ──> Controller ── Model ──> main.jsp ── 완성된 HTML ──> 브라우저
  검색·저장 ── $.ajax ──> Controller ── JSON ──> script가 HTML 문자열을 만들어 끼움

React
  브라우저 ── 처음 한 번 ──> index.html + JS 파일(앱 전체)
  그다음부터 ── fetch ──> @RestController ── JSON ──> state에 넣으면 React가 화면을 그림
```

- JSP는 서버가 HTML을 완성해서 보냅니다. 목록에 무엇이 보일지 서버에서 정해집니다.
- React는 서버가 데이터(JSON)만 보내고, 화면은 브라우저가 그립니다.
- 그래서 React 화면에서 "화면 소스 보기"를 하면 게시글이 없고 빈 틀(`<div id="root">`)만 보입니다. 실제로 그려진 화면은 개발자 도구의 Elements 탭에서 봅니다.

## 2. main.jsp 해부

`main.jsp`는 크게 두 부분입니다.

| 영역 | 들어 있는 것 | 하는 일 |
|---|---|---|
| `<script>` | 전역 변수(`currentPage`), `$(document).ready`, `fn_search`, `fn_paging`, `fn_detail`, `fn_save`, `fn_delete` | 서버를 부르고, 받은 값으로 화면을 직접 고친다 |
| `<body>` | 목록 영역, 상세 영역(숨김), 글쓰기 영역(숨김) | 화면의 틀. 첫 목록은 서버가 `<c:forEach>`로 채워서 보낸다 |

JSP 방식의 특징이 두 가지 있습니다.

- 화면을 고치는 코드가 따로 있습니다. `$('#tbody').html(html)`, `$('#detailArea').show()`처럼 "어디를 어떻게 바꿀지"를 직접 씁니다.
- 같은 목록을 그리는 코드가 두 군데입니다. 첫 화면은 `<c:forEach>`가, 검색 뒤에는 `fn_search` 안의 문자열 이어 붙이기가 그립니다. 칸을 하나 추가하려면 두 곳을 다 고쳐야 합니다.

## 3. 한 파일 React로 옮기기(BoardMain.jsx)

`BoardMain.jsx`는 `main.jsp`와 같은 배치입니다. 위에서 아래로 한 줄씩 대응됩니다.

| main.jsp | BoardMain.jsx | 관련 장 |
|---|---|---|
| `var currentPage = 1;` 같은 전역 변수 | `const [currentPage, setCurrentPage] = useState(1)` | 6, 7장 |
| `$(document).ready(function(){ ... })` | `useEffect(() => { ... }, [])` | 7장 |
| `function fn_search(page) { $.ajax(...) }` | `async function fnSearch(page) { await boardApi.list(...) }` | |
| `$('#tbody').html(html)`로 목록 다시 그리기 | `setList(res.items)` 한 줄. 화면은 React가 다시 그림 | 4장 |
| `fn_paging()`으로 버튼 다시 그리기 | 필요 없음. `totalCount`가 바뀌면 버튼도 다시 그려짐 | |
| `<c:forEach items="${list}">` | `{list.map((b) => <tr key={b.seq}>...)}` | 10장 |
| `<c:if test="...">` | `{조건 && <tr>...</tr>}` | 9장 |
| `$('#detailArea').show()`, `.hide()` | `setArea('detail')` + `{area === 'detail' && ...}` | 9장 |
| `<input type="hidden" id="seq">` | `const [detail, setDetail] = useState(null)` | |
| `$('#writeForm').serialize()` | `form` state를 그대로 보냄 | 11장 |
| `onclick="fn_search(1)"` | `onClick={() => fnSearch(1)}` | 8장 |
| `keyup`에서 `keyCode === 13`(엔터) | `<form onSubmit={...}>` | 11장 |

가장 큰 차이는 "화면을 고치는 코드"가 사라진다는 점입니다.

```js
// main.jsp: 값을 받고, 화면을 직접 고친다
$('#tbody').html(html);
fn_paging(res.totalCount);

// React: 값만 바꾼다. 화면(아래 JSX)은 그 값으로 다시 그려진다
setList(res.items);
setTotalCount(res.totalCount);
```

목록을 그리는 코드도 JSX의 `map` 한 곳뿐입니다. 칸을 추가하면 한 곳만 고치면 됩니다.

하나 밝혀 둘 점이 있습니다. `useEffect(() => { fnSearch(1); }, [])`는 "처음 한 번만 부른다"는 뜻으로 의존성 배열을 비워 둔 것입니다. React의 린트 규칙(exhaustive-deps)은 이 모양에 경고를 냅니다. 실무 코드에서는 첫 조회를 React Query 같은 라이브러리로 처리하는 경우가 많습니다. 여기서는 `$(document).ready`와 1:1로 비교하려고 가장 단순한 모양으로 썼습니다.

## 4. 컴포넌트로 나누기(BoardPage.jsx)

한 파일 버전은 읽기 쉽지만, 화면이 커지면 한 파일이 수천 줄이 됩니다(긴 main.jsp와 같은 문제). 그래서 실무에서는 화면 조각으로 나눕니다.

| 파일 | 맡은 일 | JSP에서는 |
|---|---|---|
| `BoardPage.jsx` | 조각을 배치하고, 어느 영역을 보여 줄지 정한다 | main.jsp의 전체 틀 |
| `SearchBar.jsx` | 검색창과 글쓰기 버튼 | 검색 영역 HTML |
| `BoardTable.jsx` | 목록 표 | `<table>`과 `<c:forEach>` |
| `Pagination.jsx` | 페이지 번호 버튼 | `<jsp:include page="paging.jsp"/>` |
| `BoardDetail.jsx` | 상세 화면 | `detailArea` |
| `BoardForm.jsx` | 글쓰기 폼 | `writeArea` |
| `useBoards.js` | 목록 조회 state와 함수(화면 없음) | `fn_search`와 전역 변수 |
| `boardApi.js` | 서버 호출 | 공통 ajax 함수, `$.ajax` 호출부 |

나누는 기준입니다.

1. 화면에서 눈에 보이는 덩어리(검색창, 표, 페이징)
2. 다른 화면에서도 쓸 것(페이징 버튼은 모든 목록 화면에 필요하다)
3. 화면 없이 로직만 있는 것은 훅으로(`useBoards`)
4. 서버 호출은 한 파일로(`boardApi`). 주소가 바뀌면 이 파일만 고친다

처음부터 잘게 나눌 필요는 없습니다. 한 파일로 시작해서 파일이 길어지거나 같은 코드가 두 번 나오면 그때 나눠도 됩니다.

## 5. 데이터가 흐르는 길

나눈 버전에서 가장 헷갈리는 부분입니다. 규칙은 하나입니다. 값은 위에서 아래로(props), 일어난 일은 아래에서 위로(함수) 전달합니다(12장 State 끌어올리기).

```
BoardPage (state: 목록, 현재 페이지, 보이는 영역, 상세 글)
  │ list={boards.list}            ↓ 값을 내려 준다
  ├─ BoardTable ── 행 클릭 ── onSelect(seq) ──┐
  │                                          ↑ 일어난 일을 올려 보낸다
  │                       openDetail(seq): 글을 받아 setDetail, setArea('detail')
  └─ BoardDetail(board={detail})  ← state가 바뀌어 다시 그려진다
```

`BoardTable`은 행을 눌렀을 때 무엇을 할지 모릅니다. "이 글을 눌렀다"만 알리고, 상세를 열지 말지는 `BoardPage`가 정합니다. 그래서 `BoardTable`은 다른 화면에서도 그대로 쓸 수 있습니다.

state를 어디에 둘지는 이렇게 정합니다.

| state | 쓰는 곳 | 두는 곳 |
|---|---|---|
| 목록, 현재 페이지 | 표, 페이징 | 둘의 부모(`BoardPage`, `useBoards`) |
| 보이는 영역, 상세 글 | 목록·상세·글쓰기 전환 | `BoardPage` |
| 검색창에 입력 중인 글자 | 검색창만 | `SearchBar` |
| 글쓰기 입력값 | 글쓰기 폼만 | `BoardForm` |

## 6. 서버 쪽은 어떻게 바뀌나

JSP 화면용 컨트롤러는 화면 이름을 돌려주고, React용 컨트롤러는 데이터(JSON)만 돌려줍니다.

```java
// JSP 방식: 화면 이름을 돌려준다(첫 목록은 Model에 담아서)
@Controller
public class BoardController {
    @RequestMapping("/board/main.do")
    public String main(Model model) {
        model.addAttribute("list", boardService.list("", 1));
        return "board/main";                       // → main.jsp
    }

    @ResponseBody                                  // ajax용은 JSON으로
    @RequestMapping("/board/list.do")
    public Map<String, Object> list(String keyword, int page) { ... }
}

// React 방식: 데이터만 돌려준다
@RestController
@RequestMapping("/api/boards")
public class BoardApiController {
    @GetMapping                     public BoardListResponse list(@RequestParam(defaultValue = "") String keyword,
                                                                 @RequestParam(defaultValue = "1") int page) { ... }
    @GetMapping("/{seq}")           public Board get(@PathVariable Long seq) { ... }
    @PostMapping                    public Board create(@RequestBody BoardRequest request) { ... }
    @DeleteMapping("/{seq}")        public void delete(@PathVariable Long seq) { ... }
}
```

서비스와 SQL(MyBatis Mapper)은 그대로입니다. 바뀌는 것은 화면과 컨트롤러가 주고받는 모양뿐입니다. 공부하기 > Spring Boot 6장(REST 컨트롤러)과 16장(서버 화면)에서 두 방식을 따로 볼 수 있습니다.

React와 Thymeleaf를 함께 쓰는 시스템이라면 두 흐름이 섞여 있습니다. Thymeleaf 화면은 JSP처럼 서버가 HTML을 만들고, React 화면은 API로 JSON을 받아 그립니다. 컨트롤러가 `@Controller`(화면 이름)인지 `@RestController`(JSON)인지 보면 어느 쪽인지 구분됩니다.

## 7. 운영에서 화면 문제를 볼 때

"목록이 안 나온다", "값이 이상하다"는 문의가 오면 이 순서로 봅니다.

1. F12 → Network 탭에서 화면이 부른 API를 찾습니다(`/api/boards?...`).
2. 응답 상태 코드와 내용을 봅니다.
   - 응답이 틀렸으면 서버 문제입니다. 컨트롤러 → 서비스 → SQL로 갑니다.
   - 응답은 맞는데 화면이 틀렸으면 화면 문제입니다. 그 화면 조각(컴포넌트) 파일을 봅니다.
3. 화면 조각 파일은 화면에 보이는 글자(버튼 이름, 제목)로 소스 전체를 검색하면 빨리 찾습니다.
4. React 개발자 도구(React DevTools)를 쓸 수 있으면 컴포넌트마다 props와 state 값이 보입니다.

JSP에서는 "화면 소스 보기"로 서버가 만든 HTML을 바로 봤지만, React에서는 Network 탭(데이터)과 Elements 탭(그려진 화면)을 나눠서 봅니다.

## 확인 문제

1. main.jsp의 `$('#tbody').html(html)`은 React에서 무엇으로 바뀌나요?
2. `$(document).ready(...)`에 해당하는 React 코드는?
3. main.jsp는 상세 영역을 `display:none`으로 숨겨 두었습니다. React 버전은 어떻게 하나요?
4. 검색창에 입력 중인 글자를 `BoardPage`가 아니라 `SearchBar`가 가지는 이유는?
5. `BoardTable`이 행을 눌렀을 때 직접 상세를 열지 않고 `onSelect`로 알리기만 하는 이유는?
6. React 화면에서 "화면 소스 보기"를 했더니 게시글 내용이 없습니다. 왜 그런가요?

## 정답

1. `setList(res.items)`처럼 state만 바꿉니다. 화면은 JSX의 `list.map(...)`이 다시 그립니다.
2. `useEffect(() => { ... }, [])`입니다. 화면이 처음 그려진 뒤 한 번 실행됩니다.
3. 숨기지 않고 아예 그리지 않습니다. `{area === 'detail' && ...}`처럼 조건이 맞을 때만 그립니다.
4. 그 글자는 검색창만 쓰는 값이라서입니다. 검색 버튼을 누를 때만 부모에게 단어를 넘깁니다.
5. 무엇을 할지는 부모가 정해야 `BoardTable`을 다른 화면에서도 그대로 쓸 수 있기 때문입니다.
6. React는 브라우저에서 JavaScript로 화면을 그려서, HTML 소스에는 빈 틀만 있습니다. 그려진 화면은 Elements 탭에서, 데이터는 Network 탭에서 봅니다.
