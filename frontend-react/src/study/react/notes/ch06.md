## State란?

**State = React Component의 상태, 변경 가능한 데이터**

- 렌더링이나 데이터 흐름에 **사용되는 값만** state에 포함시킵니다.
- state는 JavaScript 객체입니다.

```jsx
class LikeButton extends React.Component {
  // class가 생성될 때 실행되는 함수
  constructor(props) {
    super(props);

    // 현재 state를 정의합니다(함수 컴포넌트에서는 useState Hook으로 정의).
    this.state = {
      liked: false
    };
  }
  // ...
}
```

## State는 직접 바꾸지 않는다

```jsx
this.state = { name: 'Roy' };       // 직접 수정(잘못된 수정)
this.setState({ name: 'Roy' });     // 올바른 수정
```

**state를 바꿀 때는 반드시 `setState` 함수를 사용합니다.** 직접 대입하면 React가 변경을 알지 못해 화면이 갱신되지 않습니다.

> **AI 코멘트**
>
> 직접 대입이 안 되는 이유: React는 `setState`(또는 `useState`의 set 함수)가 호출되어야 "바뀌었다"고 알고 화면을 다시 그립니다. 같은 이유로 **객체·배열 state는 안의 내용을 직접 바꾸지 말고 새 객체/배열로 교체**해야 합니다(불변성). 배열에 추가할 때는 `push` 대신 `[...prev, item]`을 씁니다.
>
> 또 `setState`는 호출 즉시 값이 바뀌는 것이 아니라 **다음 렌더링에 반영**되고, 여러 번 호출이 합쳐질 수 있습니다. 이전 값을 바탕으로 계산할 때는 함수 형태 `setState(prev => ...)`를 씁니다.

## Lifecycle(생명주기)

> 클래스 Component 기준의 개념이고, 최근에는 잘 쓰지 않습니다(Hooks로 대체).

사람의 일생에 비유한 흐름입니다.

| 출생 | 인생 | 사망 |
|---|---|---|
| **Mounting** | **Updating** | **Unmounting** |
| `constructor` → `render` | `render` (state/props 변경 때마다) | — |
| React가 DOM과 refs를 갱신 | React가 DOM과 refs를 갱신 | — |
| `componentDidMount` | `componentDidUpdate` | `componentWillUnmount` |

- Component는 계속 존재하는 것이 아니라, **시간의 흐름에 따라 생성되고 업데이트되다가 사라집니다.**

> **AI 코멘트**
>
> 클래스의 생명주기 메서드는 Hooks에 이렇게 대응시켜 이해하면 편합니다.
>
> - `componentDidMount` ≈ `useEffect(..., [])`
> - `componentDidUpdate` ≈ 의존성이 있는 `useEffect`
> - `componentWillUnmount` ≈ `useEffect`가 돌려주는 **정리 함수**
>
> 다만 1:1 대응은 아니고, Hooks에서는 "언제 실행되나"보다 "무엇과 동기화하나"로 생각하는 편이 정확합니다(7장 코멘트 참고).
>
> 그리고 원문의 `componentDidUnmount`는 오타이고, 실제 메서드 이름은 **`componentWillUnmount`** 입니다.

## 이 챕터의 예제 (NotificationList / Notification)

**데모** 탭에서 알림이 **1초마다 하나씩** 추가됩니다. 아래 **콘솔 출력**에서 생명주기 메서드가 호출되는 순서를 눈으로 확인할 수 있습니다.

- `NotificationList`의 `componentDidMount`에서 `setInterval`로 1초마다 알림을 하나씩 `state`에 넣고 `setState`로 갱신합니다.
- 각 `Notification`은 마운트될 때 `componentDidMount()`, 갱신될 때 `componentDidUpdate()`, 사라질 때 `componentWillUnmount()` 를 로그로 남깁니다.
- 로그를 보면 알림이 추가될 때마다 **새 알림은 마운트**, **기존 알림은 업데이트**되는 것을 알 수 있습니다.

> **AI 코멘트**
>
> 이 예제의 `componentDidMount`는 `this.state.notifications` 배열에 **직접 `push`한 다음 `setState`를 호출**합니다. 화면은 갱신되지만, 위에서 말한 "state를 직접 바꾸지 않는다" 규칙을 어기는 코드입니다(생명주기 로그를 보여주려고 단순화한 학습용 코드입니다). 규칙대로 쓰면 이렇게 됩니다.
>
> ```jsx
> this.setState((prev) => ({
>   notifications: [...prev.notifications, reservedNotifications[prev.notifications.length]],
> }));
> ```
>
> 또 타이머(`timer`)가 컴포넌트 **밖의 모듈 변수**라서, 같은 컴포넌트를 두 개 띄우면 서로의 타이머를 덮어씁니다. 인스턴스마다 `this.timer`에 저장하고 `componentWillUnmount`에서 `clearInterval`하는 것이 정상입니다. 지금 코드는 `componentWillUnmount`가 없어서, 화면을 떠나도 타이머가 알림을 다 채울 때까지 계속 돕니다.
>
> **개발 모드(StrictMode)에서는** 생명주기가 두 번씩 실행되어 위의 로그가 두 배로 찍힙니다. 원본에서 "17버전으로 다운"했던 이유가 이것입니다. 이 사이트의 데모는 StrictMode 바깥의 별도 루트에서 실행해서 React 17과 같은 동작을 보여줍니다.
