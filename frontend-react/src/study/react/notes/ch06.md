## State란?

**State = React Component의 상태, 변경 가능한 데이터**

- 렌더링이나 데이터 흐름에 **사용되는 값만** state에 포함시킵니다.
- state는 JavaScript 객체입니다.

```jsx
class LikeButton extends React.Component {
  // class가 생성될 때 실행되는 함수
  constructor(props) {
    super(props);

    // 현재 state를 정의합니다(함수 컴포넌트에서는 useState Hook으로 정의).
    this.state = {
      liked: false
    };
  }
  // ...
}
```

## State는 직접 바꾸지 않는다

```jsx
this.state = { name: 'Roy' };       // 직접 수정(잘못된 수정)
this.setState({ name: 'Roy' });     // 올바른 수정
```

**state를 바꿀 때는 반드시 `setState` 함수를 사용합니다.** 직접 대입하면 React가 변경을 알지 못해 화면이 갱신되지 않습니다.

## Lifecycle(생명주기)

> 클래스 Component 기준의 개념이고, 최근에는 잘 쓰지 않습니다(Hooks로 대체).

사람의 일생에 비유한 흐름입니다.

| 출생 | 인생 | 사망 |
|---|---|---|
| **Mounting** | **Updating** | **Unmounting** |
| `constructor` → `render` | `render` (state/props 변경 때마다) | — |
| React가 DOM과 refs를 갱신 | React가 DOM과 refs를 갱신 | — |
| `componentDidMount` | `componentDidUpdate` | `componentWillUnmount` |

- Component는 계속 존재하는 것이 아니라, **시간의 흐름에 따라 생성되고 업데이트되다가 사라집니다.**
- (README 원문에는 `componentDidUnmount`로 적혀 있었는데, 실제 메서드 이름은 `componentWillUnmount` 입니다.)

## 이 챕터의 예제 (NotificationList / Notification)

**데모** 탭에서 알림이 **1초마다 하나씩** 추가됩니다. 아래 **콘솔 출력**에서 생명주기 메서드가 호출되는 순서를 눈으로 확인할 수 있습니다.

- `NotificationList`의 `componentDidMount`에서 `setInterval`로 1초마다 알림을 하나씩 `state`에 넣고 `setState`로 갱신합니다.
- 각 `Notification`은 마운트될 때 `componentDidMount()`, 갱신될 때 `componentDidUpdate()`, 사라질 때 `componentWillUnmount()` 를 로그로 남깁니다.
- 로그를 보면 알림이 추가될 때마다 **새 알림은 마운트**, **기존 알림은 업데이트**되는 것을 알 수 있습니다.

> 개발 모드의 StrictMode는 생명주기를 두 번 실행해서 로그가 두 배로 찍힙니다. 원본에서 React 17로 내려 공부했던 이유도 이것입니다. 이 사이트의 데모는 StrictMode 바깥의 별도 루트에서 실행해서 React 17과 같은 동작을 보여줍니다.
