## Component란?

- **Component-based**: 레고 블록을 조립하듯 Component를 모아서 개발합니다.
- 작은 Component들이 모여 하나의 Component를 구성하고, 그것들이 모여 전체 페이지가 됩니다.
- 하나의 Component를 반복해서 사용하므로 개발 시간과 유지보수 시간이 줄어듭니다.
- React Component는 자바스크립트의 **함수**와 비슷합니다.

> **입력(Props) → React Component → 출력(React Element)**
> 어떤 속성들을 입력으로 받아서, 그에 맞는 React Element를 생성해 return 해 주는 것

## Props란?

**Props = React Component의 속성** (붕어빵에 들어가는 재료)

- 같은 React Component에서 생성된 Element라도, Props에 따라 **Component의 모습과 속성**이 결정됩니다.
- Component에 어떤 데이터를 전달하고, 전달된 데이터에 따라 다른 모습의 Element를 화면에 렌더링할 때, 그 데이터를 Props에 넣어 전달합니다.

```jsx
function App(props) {
  return (
    <Profile
      name="소플"
      introduction="안녕하세요"
      viewCount={1500}
    />
  );
}
```

- 이 코드에는 `App` Component가 나오고, 그 안에서 `Profile` Component를 사용합니다.
- `{}` 중괄호 안에는 JavaScript 코드가 들어갑니다(`viewCount={1500}` 처럼 숫자·변수·표현식).

**참고 — JSX 없이 쓴다면**

```js
React.createElement(
  Profile,
  {
    name: "소플",
    introduction: "안녕하세요",
    viewCount: 1500
  },
  null   // 하위 Component가 없기 때문에 null이 들어갑니다.
);
```

## Props의 특징 — Read-Only

- `sum = a + b` : 항상 같은 값을 리턴한다 → **pure**
- `account.total -= amount` : 총액에서 amount를 빼서 잔액을 표현한다(입력 값을 바꿔 버림) → **impure**
- **모든 React Component는 자신의 props에 대해서는 pure 함수처럼 동작해야 합니다.**
  - 직접 props를 바꿀 수 없고,
  - 같은 props에 대해서는 항상 같은 결과를 보여줘야 합니다.

> **AI 코멘트**
>
> Props가 읽기 전용인 이유는 React의 **단방향 데이터 흐름**(부모 → 자식) 때문입니다. 자식이 받은 props를 마음대로 바꾸면 데이터가 어디서 바뀌었는지 추적하기 어려워집니다. 값을 바꿔야 하면 자식이 직접 고치지 않고, **부모가 내려준 함수를 호출**해서 부모의 state를 바꾸게 합니다(12장 state 끌어올리기).
>
> 객체나 배열 props도 `props.items.push(...)`처럼 내용을 직접 바꾸면 같은 규칙을 어기는 것입니다.

## Function Component와 Class Component

**Function Component** — 하나의 props 객체를 받아서 인삿말이 담긴 React Element를 return 합니다.

```jsx
function Welcome(props) {
  return <h1>안녕, {props.name}</h1>;
}
```

**Class Component** — JavaScript ES6의 Class로 만든 Component

```jsx
class Welcome extends React.Component {
  render() {
    return <h1>안녕, {this.props.name}</h1>;
  }
}
```

> **AI 코멘트**
>
> 새 코드는 거의 항상 **함수 컴포넌트**로 씁니다. 클래스 컴포넌트는 지금도 동작하고 오래된 코드를 읽을 때 필요하지만, 새로 만들 이유는 없습니다.
>
> 함수 컴포넌트에서는 props를 매개변수에서 바로 구조분해해서 쓰는 경우가 많습니다. 기본값도 매개변수 기본값으로 줍니다.
>
> ```jsx
> function Welcome({ name = '손님' }) {
>   return <h1>안녕, {name}</h1>;
> }
> ```
>
> 함수 컴포넌트의 `defaultProps`는 **React 19에서 제거**됐습니다.

## Component 사용과 렌더링

**Component 이름은 항상 대문자로 시작해야 합니다.** 소문자로 시작하면 DOM 태그로 인식합니다.

```jsx
const element = <div />;                  // DOM 태그를 사용한 element
const element = <Welcome name="Roy" />;   // 사용자가 정의한 Component를 사용한 element
```

**렌더링**

```jsx
function Welcome(props) {
  return <h1>안녕, {props.name}</h1>;
}

const element = <Welcome name="Roy" />;
ReactDOM.render(
  element,
  document.getElementById('root')
);
```

**Component 안에 Component 구성하기**

```jsx
function App(props) {
  return (
    <div>
      <Welcome name="Mike" />
      <Welcome name="Steve" />
      <Welcome name="Jane" />
    </div>
  );
}
```

## Component 추출

큰 Component를 쪼개서 작은 Component로 사용합니다. **재사용성이 올라갑니다.**

```jsx
function Avatar(props) {
  return (
    <img className="avatar"
      src={props.user.avatarUrl}
      alt={props.user.name}
    />
  );
}

// 사용
<Avatar user={props.author} />
```

`Avatar`를 쓰는 `UserInfo`를 다시 추출할 수 있습니다.

```jsx
function UserInfo(props) {
  return (
    <div className="user-info">
      <Avatar user={props.user} />
      <div className="user-info-name">
        {props.user.name}
      </div>
    </div>
  );
}
```

> **AI 코멘트**
>
> 흔한 실수 하나: **컴포넌트 안에서 다른 컴포넌트를 정의하지 마세요.** 부모가 렌더링될 때마다 자식 컴포넌트 정의가 새로 만들어져서 React가 매번 "다른 컴포넌트"로 보고, 그 안의 state가 초기화되거나 입력창 포커스가 사라지는 문제가 생깁니다. 컴포넌트는 파일 최상위에 정의하고 필요한 값은 props로 넘깁니다.
>
> 컴포넌트를 쪼개는 기준은 "재사용될 것 같아서"보다 **"한 컴포넌트가 하는 일이 둘 이상이거나 너무 길어져서"** 가 더 실용적입니다.
