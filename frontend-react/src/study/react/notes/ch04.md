## Element란?

- **Element**: React 앱을 구성하는 가장 작은 블록들입니다.
- **React Element vs DOM Element**: React Element는 DOM Element의 **가상 표현**입니다.

  ```jsx
  const element = <h1>Hello</h1>;
  ```

  - 대입 연산자의 오른쪽은 React의 `createElement` 함수를 사용해 Element를 생성합니다.
  - React는 이 Element를 이용해서 실제로 화면에 보이는 DOM Element를 생성합니다.
  - React Element는 **자바스크립트 객체** 형태로 존재합니다.
- Element는 Component의 유형과 속성, 내부의 모든 자식에 대한 정보를 포함하고 있는 자바스크립트 객체입니다.
- Component를 렌더링하기 위해 모든 Component가 `createElement` 함수를 통해 Element로 변환됩니다.
- 즉, React의 Element는 **우리 눈에 실제로 보이는 것을 기술**합니다.

> **AI 코멘트**
>
> 헷갈리기 쉬운 세 가지를 구분해 두면 도움이 됩니다.
>
> - **Component**: Element를 만들어 내는 함수/클래스 (붕어빵 틀)
> - **Element**: "화면에 무엇을 그릴지" 설명하는 가벼운 객체 (붕어빵)
> - **DOM Element**: 브라우저가 실제로 그리는 노드
>
> React Element 객체는 만드는 비용이 작아서, 렌더링할 때마다 새로 만들어도 부담이 크지 않습니다.

## Element의 특징 — 한번 만들면 바꿀 수 없다

- Element는 다양한 모습으로 존재할 수 있지만, **한번 생성된 다음에는 변경이 불가능**합니다.
- 붕어빵 비유: Component(붕어빵 틀) → Element(붕어빵). 구워 낸 뒤에는 내용물을 바꿀 수 없습니다.
- 화면이 바뀌어야 할 때는 **Virtual DOM이 변경된 부분을 계산**하고, 그 부분만 다시 렌더링합니다. 이때 Element가 **새로 생성**됩니다.

> **AI 코멘트**
>
> "Virtual DOM이 실제 DOM보다 빠르다"고 설명하는 자료가 많지만 정확한 표현은 아닙니다. 실제 DOM을 직접 잘 다루면 그쪽이 더 빠를 수도 있습니다. React의 핵심 이점은 속도 자체보다, 개발자가 "DOM을 어떻게 바꿀지"를 직접 쓰지 않고 **"화면이 이렇게 보여야 한다"(선언형)** 만 쓰면 React가 바뀐 부분만 반영해 준다는 점입니다.
>
> 이전 Element와 새 Element를 비교해 바뀐 부분을 찾는 과정을 **reconciliation(재조정)** 이라고 합니다. 같은 자리에 같은 종류의 요소가 오면 갱신하고, 종류가 바뀌면 새로 만듭니다. 10장의 `key`가 이 비교 과정과 연결됩니다.

## Element 렌더링

```html
<div id="root"></div>
```

- React는 **단 하나의 루트(root) DOM 노드**를 가집니다.
- root div에 React Element를 실제로 렌더링하기 위해 아래 코드를 사용합니다.

  ```jsx
  const element = <h1>Hello</h1>;
  ReactDOM.render(element, document.getElementById('root'));
  ```

> 결국 React Element가 렌더링되는 과정은 **Virtual DOM → Real DOM**으로 옮겨지는 과정입니다.

## 이 챕터의 예제 (Clock)

**데모** 탭의 시계는 1초마다 화면을 다시 그립니다. `Clock` 컴포넌트는 렌더링될 때마다 `new Date()`로 현재 시간을 새로 계산해서 **새 Element**를 만들고, React는 달라진 부분(시간 글자)만 실제 DOM에 반영합니다.

원본은 `index.js`에서 `setInterval`로 `root.render(<Clock />)`을 1초마다 다시 호출했습니다.

```jsx
const root = ReactDOM.createRoot(document.getElementById('root'));

setInterval(() => {
  root.render(
    <React.StrictMode>
      <Clock />
    </React.StrictMode>
  );
}, 1000);
```

> **AI 코멘트**
>
> 원본처럼 `setInterval`로 루트 전체를 다시 렌더링하는 방식은 "Element가 새로 만들어진다"는 점을 보여주려는 학습용입니다. 실제 앱에서는 시간을 `state`로 두고, `useEffect`로 타이머를 시작하면서 컴포넌트가 사라질 때 타이머를 지우는 **정리 함수(cleanup)** 를 함께 씁니다(7장). 정리하지 않으면 화면을 떠난 뒤에도 타이머가 계속 돌아 메모리 누수와 오류의 원인이 됩니다.
>
> ```jsx
> function Clock() {
>   const [now, setNow] = useState(() => new Date());
>
>   useEffect(() => {
>     const timer = setInterval(() => setNow(new Date()), 1000);
>     return () => clearInterval(timer);   // 화면에서 사라질 때 정리
>   }, []);
>
>   return <h2>현재 시간 : {now.toLocaleTimeString()}</h2>;
> }
> ```
