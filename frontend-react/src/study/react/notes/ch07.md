> 주황색 **💬 AI 코멘트**는 AI가 덧붙인 설명입니다. 내가 정리한 원문과 구분되도록 따로 표시했고, 위쪽 스위치로 숨길 수 있습니다.

## Hooks란?

- **Function Component**는 원래 state를 쓸 수 없고, Lifecycle에 따른 기능도 구현할 수 없었습니다.
- **Hooks**를 사용하면 Function Component에서도 Class Component처럼 쓸 수 있습니다(React **16.8** 이후 도입).
- 종류: `useState`, `useEffect`, `useContext`, `useReducer`, `useRef`, `useMemo`, `useCallback`

**특징**

- 클래스형 Component를 대체합니다.
- 관련 로직을 작은 단위로 분리해서 **재사용성과 가독성**을 높입니다.
- Hook은 Component의 **최상위 레벨에서만** 호출할 수 있고, 조건문 안에서는 사용할 수 없습니다.

> **AI 코멘트**
>
> 목록에 이름만 있던 **`useReducer`** 는 state를 바꾸는 규칙을 `(state, action) => 새 state` 함수 한곳에 모아 두는 Hook입니다. 서로 연관된 state가 여러 개이거나 업데이트 종류가 많아지면, `useState`를 여러 개 두고 곳곳에서 바꾸는 것보다 읽기 쉽고 실수가 줄어듭니다. 값 하나를 켰다 끄는 정도라면 `useState`로 충분합니다.

## useState — state를 사용하기 위한 Hook

**일반 변수로는 화면이 갱신되지 않습니다.** 아래 코드는 클릭해도 숫자가 바뀌지 않습니다(값은 바뀌어도 React가 다시 렌더링하지 않기 때문).

```jsx
function Counter(props) {
  var count = 0;

  return (
    <div>
      <p>총 {count}번 클릭했습니다.</p>
      <button onClick={() => count++}>클릭</button>
    </div>
  );
}
```

**`useState`로 바꾸면** 값이 바뀔 때 다시 렌더링됩니다.

```jsx
const [변수명, set함수명] = useState(초기값);
```

```jsx
import React, { useState } from "react";

// 변수 각각에 대해 set 함수가 따로 존재합니다.
function Counter(props) {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>총 {count}번 클릭했습니다.</p>
      <button onClick={() => setCount(count + 1)}>클릭</button>
    </div>
  );
}
```

> **AI 코멘트**
>
> set 함수는 값을 바꿔 **다음 렌더링에** 반영합니다. 그래서 `setCount(count + 1)`을 연달아 세 번 불러도 모두 **같은 `count`** 를 기준으로 계산해서 1만 늘어납니다. 이전 값에 의존할 때는 함수를 넘기세요.
>
> ```jsx
> setCount(c => c + 1);   // 항상 "직전 값"을 기준으로 계산
> ```
>
> 객체·배열 state는 `setUser({ ...user, name })`처럼 **새로 만들어 교체**합니다(6장).

## useEffect — Side effect를 수행하기 위한 Hook

기본 형태: `useEffect(이펙트 함수, 의존성 배열)`

```jsx
useEffect(() => {
  // 컴포넌트가 마운트된 이후, 의존성 배열의 변수 중 하나라도 값이 바뀌었을 때 실행됩니다.

  return () => {
    // 컴포넌트가 마운트 해제되기 전에 실행됩니다. (정리, cleanup)
  };
}, [의존성 변수1, 의존성 변수2]);
```

| 의존성 배열 | 실행 시점 |
|---|---|
| `[변수1, 변수2]` | 마운트 이후, 배열의 변수 중 **하나라도 바뀔 때** |
| `[]` (빈 배열) | 마운트와 언마운트 시에 **단 한 번씩만** |
| 생략 | 컴포넌트가 **업데이트될 때마다** |

**예제 1 — `componentDidMount`, `componentDidUpdate`와 비슷하게 동작**

```jsx
function Counter(props) {
  const [count, setCount] = useState(0);

  useEffect(() => {
    // 브라우저 API를 사용해서 document의 title을 업데이트
    document.title = `You clicked ${count} times`;
  });

  return (
    <div>
      <p>총 {count}번 클릭했습니다.</p>
      <button onClick={() => setCount(count + 1)}>클릭</button>
    </div>
  );
}
```

**예제 2 — 구독과 정리(cleanup)**

```jsx
function UserStatus(props) {
  const [isOnline, setIsOnline] = useState(null);

  function handleStatusChange(status) {
    setIsOnline(status.isOnline);
  }

  useEffect(() => {
    ServerAPI.subscribeUserStatus(props.user.id, handleStatusChange);

    // Component가 unmount될 때 호출됩니다.
    return () => {
      ServerAPI.unsubscribeUserStatus(props.user.id, handleStatusChange);
    };
  });

  if (isOnline === null) {
    return '대기 중...';
  }
  return isOnline ? '온라인' : '오프라인';
}
```

**예제 3 — 한 Component에서 여러 개의 Effect 사용**

```jsx
function UserStatusWithCounter(props) {
  const [count, setCount] = useState(0);
  useEffect(() => {
    document.title = `총 ${count}번 클릭했습니다.`;
  });

  const [isOnline, setIsOnline] = useState(null);
  useEffect(() => {
    ServerAPI.subscribeUserStatus(props.user.id, handleStatusChange);
    return () => {
      ServerAPI.unsubscribeUserStatus(props.user.id, handleStatusChange);
    };
  });

  function handleStatusChange(status) {
    setIsOnline(status.isOnline);
  }
  // ...
}
```

서로 관련 없는 로직(제목 변경 / 온라인 상태 구독)을 **Effect 단위로 나눠서** 쓸 수 있습니다.

> **AI 코멘트**
>
> `useEffect`를 "`componentDidMount` + `componentDidUpdate`"로 외우면 틀리기 쉽습니다. 요즘 권장하는 사고방식은 **"이 컴포넌트를 외부 시스템(타이머, 구독, 서버, 브라우저 API)과 동기화한다"** 입니다. 그래서 점검할 것은 "언제 실행되나"가 아니라 **"이 effect가 쓰는 값이 의존성 배열에 다 들어 있나"** 입니다.
>
> - 의존성 배열에서 값을 빠뜨리면 **오래된 값을 쓰는 버그**(stale closure)가 생깁니다. ESLint의 `react-hooks/exhaustive-deps` 규칙이 이를 잡아 줍니다.
> - 정리 함수는 언마운트 때만이 아니라 **다음 effect가 실행되기 직전에도** 호출됩니다.
> - 개발 모드의 StrictMode는 effect를 일부러 한 번 더 실행해서 정리 함수가 빠져 있는지 확인시켜 줍니다. 6장에서 로그가 두 번 찍힌 것이 이 현상이고, 배포 빌드에서는 한 번만 실행됩니다.
> - 서버 데이터를 불러올 때는 **이전 요청의 응답이 나중에 도착해 화면을 덮어쓰는 문제**(경쟁 상태)가 생길 수 있어서, 정리 함수에서 "이 요청 결과는 무시"라고 표시해 두는 패턴을 씁니다.

## useMemo — Memoized value를 리턴하는 Hook

**Memoization**: 최적화를 위해 사용하는 개념으로, 이전에 호출했던 결과를 저장해 두었다가 바로 받아 씁니다.

```jsx
const memoizedValue = useMemo(
  () => {
    // 연산량이 높은 작업을 수행하여 결과를 반환
    return computeExpensiveValue(의존성 변수1, 의존성 변수2);
  },
  [의존성 변수1, 의존성 변수2]
);
```

- 의존성 배열의 값이 바뀔 때만 다시 계산합니다.
- 아래 두 예제는 의존성 배열을 **생략**한 경우(렌더링마다 계산)와 **빈 배열 `[]`** 인 경우(마운트 시 한 번만 계산)입니다.

```jsx
// 의존성 배열 생략 → 매 렌더링마다 계산
const memoizedValue = useMemo(() => computeExpensiveValue(a, b));

// 빈 배열 → 마운트될 때만 계산
const memoizedValue = useMemo(() => {
  return computeExpensiveValue(a, b);
}, []);
```

## useCallback — 값이 아닌 **함수**를 반환

`useMemo`와 비슷하지만 값이 아니라 **함수 자체**를 기억합니다.

```jsx
const memoizedCallback = useCallback(
  () => {
    doSomething(의존성 변수1, 의존성 변수2);
  },
  [의존성 변수1, 의존성 변수2]
);
```

**동일한 역할을 하는 두 줄의 코드**

```jsx
useCallback(함수, 의존성 배열);
useMemo(() => 함수, 의존성 배열);
```

```jsx
function ParentComponent(props) {
  const [count, setCount] = useState(0);

  // (1) 그냥 정의: 재렌더링될 때마다 매번 함수가 새로 정의됩니다.
  const handleClick = (event) => {
    // 클릭 이벤트 처리
  };

  // (2) useCallback 사용: 컴포넌트가 마운트될 때만 함수가 정의됩니다.
  const handleClick = useCallback((event) => {
    // 클릭 이벤트 처리
  }, []);

  return (
    <div>
      <button onClick={() => { setCount(count + 1); }}>
        {count}
      </button>

      <ChildComponent handleClick={handleClick} />
    </div>
  );
}
```

위 (1)과 (2)는 **둘 중 하나를 고르는** 방식입니다.

> **AI 코멘트**
>
> `useMemo`/`useCallback`은 **성능 문제가 실제로 확인된 뒤에** 쓰는 도구입니다. 미리 곳곳에 붙이면 코드는 복잡해지는데 얻는 것은 거의 없고, 메모이제이션 자체에도 비용이 듭니다. 쓸 만한 경우는 다음 정도입니다.
>
> 1. 정말 **무거운 계산**을 렌더링마다 반복할 때
> 2. `React.memo`로 감싼 자식에게 함수·객체를 props로 넘길 때, **참조가 매번 바뀌어 자식이 불필요하게 다시 렌더링되는 것**을 막을 때 (`useCallback`을 쓰면 부모가 다시 렌더링돼도 같은 함수가 전달됩니다)
> 3. 다른 Hook의 의존성 배열에 들어가는 함수·객체의 **참조를 고정**할 때
>
> 참고로 React Compiler가 이런 메모이제이션을 자동으로 해 주는 방향으로 가고 있어서, 수동으로 붙이는 일은 점점 줄어드는 추세입니다.

## useRef — Reference를 사용하기 위한 Hook

- 특정 Component(또는 DOM 요소)에 접근할 수 있는 객체이고, `refObject.current` 로 접근합니다.
- `const refContainer = useRef(초깃값);`

```jsx
function TextInputWithFocusButton(props) {
  const inputElem = useRef(null);

  const onButtonClick = () => {
    // `current`는 마운트된 input element를 가리킵니다.
    inputElem.current.focus();
  };

  return (
    <>
      <input ref={inputElem} type="text" />
      <button onClick={onButtonClick}>Focus the input</button>
    </>
  );
}
```

- `<div ref={myRef} />` 처럼 DOM에 연결할 수 있고, 다양한 변수를 저장해 둘 수도 있습니다.
- `useRef`는 내부의 데이터가 **변경되어도 별도로 알리지(재렌더링하지) 않습니다.**

**Callback ref**

```jsx
function MeasureExample(props) {
  const [height, setHeight] = useState(0);

  const measureRef = useCallback(node => {
    if (node !== null) {
      setHeight(node.getBoundingClientRect().height);
    }
  }, []);

  return (
    <>
      <h1 ref={measureRef}>안녕, 리액트</h1>
      <h2>위 헤더의 높이는 {Math.round(height)}px 입니다.</h2>
    </>
  );
}
```

> **AI 코멘트**
>
> `useRef`는 두 가지 용도로 씁니다. ① **DOM 요소에 접근**(위 예제), ② **렌더링과 상관없이 유지해야 하는 값**(타이머 id, 이전 값, 외부 라이브러리 인스턴스)을 담아 두는 용도입니다. `.current`를 바꿔도 다시 렌더링되지 않는다는 점이 `useState`와의 결정적 차이입니다.
>
> 이 프로젝트의 `PinballBoard`도 `useRef`로 보드 DOM과 순위 목록 DOM을 잡아서, React 밖에서 DOM을 직접 다루는 게임 엔진에 넘겨줍니다.

## Hook의 규칙

1. **Hook은 무조건 최상위 레벨에서만 호출**해야 합니다. → 컴포넌트가 렌더링될 때마다 **매번 같은 순서로** 호출되어야 합니다.

   ```jsx
   function MyComponent(props) {
     const [name, setName] = useState('Inje');

     if (name !== '') {
       useEffect(() => {   // ❌ 조건문 안에서 Hook 호출 — 하면 안 됩니다.
         // ...
       });
     }
     // ...
   }
   ```

2. **React 함수 Component(와 Custom Hook)에서만** Hook을 호출해야 합니다.

**플러그인**: `eslint-plugin-react-hooks` — Hook의 규칙을 강제로 따르도록 도와주는 도구입니다.

> **AI 코멘트**
>
> 이 규칙은 React가 Hook을 **호출 순서**로 구분하기 때문에 생깁니다. 변수 이름이 아니라 "몇 번째 `useState`인가"로 state를 찾습니다. 그래서 조건문·반복문 안에서 부르면 렌더링마다 순서가 달라져 state가 엉뚱한 곳에 연결됩니다.
>
> 이 프로젝트의 린터(oxlint)에도 `react/rules-of-hooks` 규칙이 오류 수준으로 켜져 있습니다. 조건에 따라 effect를 실행하고 싶다면 Hook을 조건문 안에 넣지 말고, **effect 안에서 `if`로 분기**합니다.

## Custom Hook 만들기

**Custom Hook의 이름은 꼭 `use`로 시작**해야 합니다.

**① Custom Hook이 필요한 상황** — 두 Component에 거의 같은 구독 로직이 반복됩니다.

```jsx
function UserStatus(props) {
  const [isOnline, setIsOnline] = useState(null);

  useEffect(() => {
    function handleStatusChange(status) {
      setIsOnline(status.isOnline);
    }

    ServerAPI.subscribeUserStatus(props.user.id, handleStatusChange);
    return () => {
      ServerAPI.unsubscribeUserStatus(props.user.id, handleStatusChange);
    };
  });

  if (isOnline === null) {
    return '대기중...';
  }
  return isOnline ? '온라인' : '오프라인';
}
```

```jsx
function UserListItem(props) {
  const [isOnline, setIsOnline] = useState(null);

  useEffect(() => {
    function handleStatusChange(status) {
      setIsOnline(status.isOnline);
    }

    ServerAPI.subscribeUserStatus(props.user.id, handleStatusChange);
    return () => {
      ServerAPI.unsubscribeUserStatus(props.user.id, handleStatusChange);
    };
  });

  return (
    <li style={{ color: isOnline ? 'green' : 'black' }}>
      {props.user.name}
    </li>
  );
}
```

**② 두 Component에서 Custom Hook 사용하기** (`useUserStatus`의 구현은 아래 AI 코멘트 참고)

```jsx
function UserStatus(props) {
  const isOnline = useUserStatus(props.user.id);

  if (isOnline === null) {
    return '대기중...';
  }
  return isOnline ? '온라인' : '오프라인';
}

function UserListItem(props) {
  const isOnline = useUserStatus(props.user.id);

  return (
    <li style={{ color: isOnline ? 'green' : 'black' }}>
      {props.user.name}
    </li>
  );
}
```

**여러 Component가 하나의 Custom Hook을 써도**

- Component 내부의 모든 state와 effect는 **전부 분리**되어 있습니다.
- Custom Hook을 호출할 때마다 **분리된 state**를 얻고, 각 호출은 **완전히 독립적**입니다.

> **AI 코멘트**
>
> 원문에는 `useUserStatus`의 구현이 빠져 있어서 채워 넣었습니다. ①의 두 컴포넌트에 반복되던 구독 로직을 그대로 옮긴 것입니다.
>
> ```jsx
> function useUserStatus(userId) {
>   const [isOnline, setIsOnline] = useState(null);
>
>   useEffect(() => {
>     function handleStatusChange(status) {
>       setIsOnline(status.isOnline);
>     }
>
>     ServerAPI.subscribeUserStatus(userId, handleStatusChange);
>     return () => {
>       ServerAPI.unsubscribeUserStatus(userId, handleStatusChange);
>     };
>   });
>
>   return isOnline;
> }
> ```
>
> Custom Hook이 공유하는 것은 **로직**이지 **state가 아닙니다.** 위에서 정리한 대로 호출할 때마다 독립된 state를 얻습니다. 여러 컴포넌트가 같은 값을 보게 하려면 state를 끌어올리거나(12장) Context(14장)를 써야 합니다. 이 챕터 예제의 `useCounter`가 가장 단순한 Custom Hook입니다.

## Hook들 사이에서 데이터 공유하기

```jsx
const userList = [
  { id: 1, name: 'Inje' },
  { id: 2, name: 'Mike' },
  { id: 3, name: 'Steve' },
];

function ChatUserSelector(props) {
  // useState로 userId state를 만들고, 다음의 useUserStatus Hook의 파라미터로 넘깁니다.
  // setUserId로 사용자 아이디가 바뀌면 useUserStatus Hook은
  // 이전 사용자의 구독을 취소하고, 새로 선택된 사용자의 온라인 여부를 구독합니다.
  const [userId, setUserId] = useState(1);
  const isUserOnline = useUserStatus(userId);

  return (
    <>
      <Circle color={isUserOnline ? 'green' : 'red'} />
      <select
        value={userId}
        onChange={event => setUserId(Number(event.target.value))}
      >
        {userList.map(user => (
          <option key={user.id} value={user.id}>
            {user.name}
          </option>
        ))}
      </select>
    </>
  );
}
```

## 이 챕터의 예제 (Accommodate / useCounter)

**데모** 탭의 `Accommodate`는 입장/퇴장 인원을 관리합니다. 직접 만든 Custom Hook `useCounter`로 인원 수와 증감 함수를 가져오고, `useEffect` 두 개를 씁니다.

- 의존성 배열이 **없는** 첫 번째 `useEffect`: 렌더링될 때마다 실행(콘솔에 `useEffect() is called.`)
- 의존성이 `[count]`인 두 번째 `useEffect`: 인원 수가 바뀔 때만 실행되어 정원(10명) 초과 여부 `isFull`을 갱신
- **콘솔 출력**에서 입장 버튼을 누를 때마다 어떤 effect가 언제 실행되는지 확인해 보세요.

> **AI 코멘트**
>
> `Accommodate`의 두 번째 `useEffect`는 `count`가 바뀔 때마다 `setIsFull(count >= MAX_CAPACITY)`를 호출합니다. 동작은 하지만 **`isFull`은 `count`에서 바로 계산할 수 있는 값**이라 state로 둘 필요가 없습니다. state로 두면 렌더링이 한 번 더 일어나고(`count` 변경 → 렌더링 → effect → `isFull` 변경 → 다시 렌더링), 두 값이 잠깐 어긋나는 순간이 생깁니다. 이렇게 쓰는 편이 더 단순합니다.
>
> ```jsx
> const [count, increaseCount, decreaseCount] = useCounter(0);
> const isFull = count >= MAX_CAPACITY;   // state도 effect도 필요 없음
> ```
>
> 이 프로젝트의 린터도 이 패턴을 "effect 안에서 state를 바로 설정한다"는 경고(`set-state-in-effect`)로 알려 줍니다. 다만 이 예제는 effect가 실행되는 시점을 콘솔로 관찰하려는 학습용이라 일부러 이렇게 둔 것입니다.
