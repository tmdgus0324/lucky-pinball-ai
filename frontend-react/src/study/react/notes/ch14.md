## Context란?

기존에는 **props를 통해** 데이터를 한 단계씩 아래로 전달했습니다. **Context**는 데이터를 필요로 하는 Component에 **곧바로 전달**하는 방법입니다.

- 중간 단계를 거치지 않습니다(단계 ×).
- 데이터 흐름을 추적하기 좋습니다(디버깅에 유리).
- 어떤 데이터에 쓰나: **로그인 여부, 로그인 정보, UI 테마, 현재 언어** 등 앱 전체에서 공통으로 쓰는 값
- 단점: Context를 쓰는 Component는 **재사용성이 떨어집니다.** (그 Context가 있어야만 동작하기 때문)

> **AI 코멘트**
>
> Context는 "상태 관리 도구"가 아니라 **값을 멀리 전달하는 통로**입니다. 그래서 알아 둘 점이 있습니다.
>
> - Provider의 `value`가 바뀌면 그 Context를 읽는 **모든 컴포넌트가 다시 렌더링**됩니다. 테마·로그인 정보·언어처럼 **드물게 바뀌는 값**에는 잘 맞지만, 입력값처럼 **자주 바뀌는 값**을 담으면 화면 전체가 자주 다시 그려질 수 있습니다.
> - props를 여러 단계 내려보내는 불편(prop drilling)을 줄여 주지만, 데이터가 어디서 오는지가 코드에서 덜 보이게 됩니다. 한두 단계면 그냥 props가 더 명확합니다(12장).

## Context API

1. **컨텍스트를 생성**합니다.
2. **`Context.Provider`** 로 하위 Component들을 감싸서 값을 내려줍니다. Provider의 `value`가 바뀌었는지는 **`Object.is` 방식**으로 비교해서 판단합니다.

> **AI 코멘트**
>
> 이 챕터 예제의 구조입니다. 3단계로 이루어집니다.
>
> ```jsx
> // 1. 컨텍스트 생성 (초기값은 따로 설정하지 않았습니다)
> const ThemeContext = React.createContext();
> ThemeContext.displayName = "ThemeContext";
> ```
>
> ```jsx
> // 2. Provider로 감싸고 value로 값을 내려줍니다.
> function DarkOrLight(props) {
>   const [theme, setTheme] = useState("light");
>
>   const toggleTheme = useCallback(() => {
>     if (theme == "light") {
>       setTheme("dark");
>     } else if (theme == "dark") {
>       setTheme("light");
>     }
>   }, [theme]);
>
>   return (
>     <ThemeContext.Provider value={{ theme, toggleTheme }}>
>       <MainContent />
>     </ThemeContext.Provider>
>   );
> }
> ```
>
> ```jsx
> // 3. 하위 Component가 props 없이 useContext로 바로 꺼내 씁니다.
> function MainContent(props) {
>   const { theme, toggleTheme } = useContext(ThemeContext);
>
>   return (
>     <div style={{ backgroundColor: theme == "light" ? "white" : "black",
>                   color: theme == "light" ? "black" : "white" }}>
>       <p>안녕하세요, 테마 변경이 가능한 웹사이트 입니다.</p>
>       <button onClick={toggleTheme}>테마 변경</button>
>     </div>
>   );
> }
> ```
>
> `MainContent`는 `theme`과 `toggleTheme`을 **props로 받지 않습니다.** `DarkOrLight`와 `MainContent` 사이에 컴포넌트가 몇 단계 더 있어도 그대로 전달됩니다.

> **AI 코멘트**
>
> 원문의 "`Object.is`로 비교한다"가 실제로 의미하는 바입니다. `value={{ theme, toggleTheme }}`처럼 객체를 직접 쓰면 `DarkOrLight`가 렌더링될 때마다 **새 객체**가 만들어지므로 `Object.is` 비교는 항상 "바뀌었다"고 판단하고, Context를 읽는 모든 컴포넌트가 다시 렌더링됩니다. 이 예제 규모에서는 문제가 없습니다.
>
> 흥미로운 점은 `toggleTheme`을 `useCallback`으로 감쌌는데도 `value` 객체가 매번 새로 만들어져서 그 효과가 거의 없다는 것입니다. 효과를 보려면 value 객체도 `useMemo`로 고정해야 합니다.
>
> ```jsx
> const value = useMemo(() => ({ theme, toggleTheme }), [theme, toggleTheme]);
> return <ThemeContext.Provider value={value}>...</ThemeContext.Provider>;
> ```

> **AI 코멘트**
>
> - 이 예제는 `createContext()`에 **기본값을 주지 않았습니다.** 그래서 Provider 밖에서 `useContext(ThemeContext)`를 쓰면 `undefined`가 되어 `const { theme } = ...`에서 오류가 납니다. 보통은 이를 감싸는 **Custom Hook**(`useTheme`)을 만들어 "Provider 안에서 써야 합니다"라는 명확한 오류 메시지를 던지게 합니다.
> - **React 19**부터는 `<ThemeContext.Provider value={...}>` 대신 `<ThemeContext value={...}>`로 쓸 수 있고, `.Provider` 형태는 앞으로 단계적으로 없어질 예정입니다. 또 `use(ThemeContext)`로 Context를 읽을 수도 있습니다(`useContext`와 달리 조건문 안에서도 호출 가능).

## 이 챕터의 예제 (DarkOrLight / MainContent / ThemeContext)

**데모** 탭의 **테마 변경** 버튼을 누르면 상자의 배경과 글자색이 라이트/다크로 바뀝니다. 원본은 화면 전체(`100vw × 100vh`)를 쓰도록 만든 예제여서, 웹 데모에서는 상자 안에 맞춰 보여줍니다.
