## Context란?

기존에는 **props를 통해** 데이터를 한 단계씩 아래로 전달했습니다. **Context**는 데이터를 필요로 하는 Component에 **곧바로 전달**하는 방법입니다.

- 중간 단계를 거치지 않습니다(단계 ×).
- 데이터 흐름을 추적하기 좋습니다(디버깅에 유리).
- 어떤 데이터에 쓰나: **로그인 여부, 로그인 정보, UI 테마, 현재 언어** 등 앱 전체에서 공통으로 쓰는 값
- 단점: Context를 쓰는 Component는 **재사용성이 떨어집니다.** (그 Context가 있어야만 동작하기 때문)

## Context API

1. **컨텍스트를 생성**합니다.
2. **`Context.Provider`** 로 하위 Component들을 감싸서 값을 내려줍니다. Provider의 `value`가 바뀌었는지는 **`Object.is` 방식**으로 비교해서 판단합니다.

**(보충)** 이 챕터 예제의 구조입니다.

```jsx
// 1. 컨텍스트 생성 (초기값은 따로 설정하지 않았습니다)
const ThemeContext = React.createContext();
ThemeContext.displayName = "ThemeContext";
```

```jsx
// 2. Provider로 감싸고 value로 값을 내려줍니다.
function DarkOrLight(props) {
  const [theme, setTheme] = useState("light");

  const toggleTheme = useCallback(() => {
    if (theme == "light") {
      setTheme("dark");
    } else if (theme == "dark") {
      setTheme("light");
    }
  }, [theme]);

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      <MainContent />
    </ThemeContext.Provider>
  );
}
```

```jsx
// 3. 하위 Component가 props 없이 useContext로 바로 꺼내 씁니다.
function MainContent(props) {
  const { theme, toggleTheme } = useContext(ThemeContext);

  return (
    <div style={{ backgroundColor: theme == "light" ? "white" : "black",
                  color: theme == "light" ? "black" : "white" }}>
      <p>안녕하세요, 테마 변경이 가능한 웹사이트 입니다.</p>
      <button onClick={toggleTheme}>테마 변경</button>
    </div>
  );
}
```

- `MainContent`는 `theme`과 `toggleTheme`을 **props로 받지 않습니다.** `DarkOrLight`와 `MainContent` 사이에 Component가 몇 단계 더 있어도 그대로 전달됩니다.
- **(보충)** `Provider`의 `value`에 `{ theme, toggleTheme }` 객체를 직접 넣으면 `DarkOrLight`가 렌더링될 때마다 **새 객체**가 만들어져서 `Object.is` 비교가 "바뀌었다"고 판단합니다. 그래서 하위 Component가 불필요하게 다시 렌더링될 수 있습니다. (이 예제 규모에서는 문제가 없지만, 큰 앱에서는 `useMemo`로 value를 고정하곤 합니다.)

## 이 챕터의 예제 (DarkOrLight / MainContent / ThemeContext)

**데모** 탭의 **테마 변경** 버튼을 누르면 상자의 배경과 글자색이 라이트/다크로 바뀝니다. 원본은 화면 전체(`100vw × 100vh`)를 쓰도록 만든 예제여서, 웹 데모에서는 상자 안에 맞춰 보여줍니다.
