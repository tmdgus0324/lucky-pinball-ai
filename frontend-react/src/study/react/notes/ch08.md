## Event란?

**Event = 사건.** 버튼 클릭 같은 사용자의 동작이고, 이를 처리하는 것을 이벤트 **핸들링**이라고 합니다.

```jsx
// React의 Event — camelCase, 함수를 직접 전달
<button onClick={activate}>
  Activate
</button>

// DOM의 Event — 소문자, 문자열로 함수 호출
<button onclick="activate()">
  Activate
</button>
```

> **AI 코멘트**
>
> `onClick`에 넘기는 것은 **함수 자체**입니다. `onClick={handleClick}`은 맞고 `onClick={handleClick()}`은 틀립니다. 괄호를 붙이면 클릭할 때가 아니라 **렌더링할 때 바로 실행**되고, 그 반환값(보통 `undefined`)이 핸들러로 등록됩니다. 인자가 필요하면 `onClick={() => handleDelete(id)}`처럼 화살표 함수로 감쌉니다.
>
> 핸들러가 받는 `event`는 브라우저 이벤트를 감싼 객체(SyntheticEvent)이고, 기본 동작을 막으려면 `event.preventDefault()`를 씁니다. HTML에서처럼 `return false`로는 막을 수 없습니다.

## Event Handler

**Event Handler = 어떤 사건이 발생하면 그 사건을 처리하는 역할** (Event Listener)

**클래스 Component — `this` 바인딩이 필수**

```jsx
class Toggle extends React.Component {
  constructor(props) {
    super(props);

    this.state = { isToggleOn: true };

    // callback에서 `this`를 사용하기 위해서는 바인딩을 필수적으로 해줘야 합니다.
    this.handleClick = this.handleClick.bind(this);
  }

  handleClick() {
    this.setState(prevState => ({
      isToggleOn: !prevState.isToggleOn
    }));
  }

  render() {
    return (
      <button onClick={this.handleClick}>
        {this.state.isToggleOn ? '켜짐' : '꺼짐'}
      </button>
    );
  }
}
```

**바인딩을 안 쓰는 방법 ① — Class fields syntax**

```jsx
class MyButton extends React.Component {
  // Class fields syntax 사용(화살표 함수가 this를 자동으로 잡아 줍니다)
  handleClick = () => {
    console.log('this is:', this);
  }

  render() {
    return (
      <button onClick={this.handleClick}>
        클릭
      </button>
    );
  }
}
```

**바인딩을 안 쓰는 방법 ② — 호출하는 쪽에서 화살표 함수**

```jsx
class MyButton extends React.Component {
  handleClick() {
    console.log('this is:', this);
  }

  render() {
    // 이렇게 하면 'this'가 바운드됩니다.
    return (
      <button onClick={() => this.handleClick()}>
        클릭
      </button>
    );
  }
}
```

> **AI 코멘트**
>
> `this` 바인딩 문제는 React의 규칙이 아니라 **JavaScript가 `this`를 정하는 방식** 때문입니다. `onClick={this.handleClick}`처럼 메서드를 함수로만 넘기면, 나중에 호출될 때는 `this`가 클래스 인스턴스를 가리키지 않아 `undefined`가 됩니다. 클래스 필드의 화살표 함수(`handleClick = () => {...}`)는 `this`를 정의된 자리에 고정해 주는 방식입니다.
>
> 함수 컴포넌트에는 `this` 자체가 없어서 이 문제가 사라집니다. 함수 컴포넌트가 선호되는 이유 중 하나입니다.

## 함수 Component에서는?

함수 Component에는 `this`가 없으므로 **바인딩이 필요 없습니다.** 위의 `Toggle`을 함수 Component로 바꾸면 다음과 같습니다.

```jsx
function Toggle(props) {
  const [isToggleOn, setIsToggleOn] = useState(true);

  // 방법 1. 함수 안에 함수로 정의
  function handleClick() {
    setIsToggleOn((isToggleOn) => !isToggleOn);
  }

  // 방법 2. arrow function을 사용하여 정의 (둘 중 하나만 씁니다)
  const handleClick = () => {
    setIsToggleOn((isToggleOn) => !isToggleOn);
  }

  return (
    // this를 쓰지 않아도 됩니다.
    <button onClick={handleClick}>
      {isToggleOn ? "켜짐" : "꺼짐"}
    </button>
  );
}
```

## Arguments 전달하기

핸들러에 **매개변수(함수에 전달할 데이터)** 를 넘기는 방법입니다.

**클래스 Component**

```jsx
// Arrow function 사용
<button onClick={(event) => this.deleteItem(id, event)}>삭제하기</button>

// 바인딩 사용 (이 경우 event는 id 다음 인자로 자동 전달됩니다)
<button onClick={this.deleteItem.bind(this, id)}>삭제하기</button>
```

**함수 Component**

```jsx
function MyButton(props) {
  const handleDelete = (id, event) => {
    console.log(id, event.target);
  };

  return (
    <button onClick={(event) => handleDelete(1, event)}>
      삭제하기
    </button>
  );
}
```

> **AI 코멘트**
>
> `onClick={() => handleDelete(1, event)}`처럼 렌더링마다 새 화살표 함수가 만들어지는 것이 성능에 나쁘지 않느냐는 질문을 자주 합니다. 대부분의 경우 무시할 수준이고, 실제로 느려졌을 때 `useCallback`/`React.memo`를 고려하면 됩니다(7장).

## 이 챕터의 예제 (ConfirmButton / ConfirmButton2)

**데모** 탭에는 같은 "확인하기" 버튼을 두 방식으로 나란히 보여줍니다.

- **ConfirmButton** — 클래스 Component. `state`로 확인 여부를 관리하고, 핸들러는 **화살표 함수(class fields)** 로 만들어 `this` 바인딩 문제를 피했습니다. 코드에는 `bind`를 쓰는 방식이 주석으로 남아 있습니다.
- **ConfirmButton2** — 함수 Component. `useState`로 같은 동작을 더 짧게 만들었습니다.
- 두 버튼 모두 누르면 "확인됨"으로 바뀌고 비활성화됩니다.
