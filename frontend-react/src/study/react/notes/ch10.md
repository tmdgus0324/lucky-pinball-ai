## List와 Key란?

- **List** = 목록. 자바스크립트에서는 배열(Array)입니다. `const numbers = [1, 2, 3, 4, 5];`
- **Key** = 열쇠, 고유값. 각 개체나 아이템을 구분할 수 있는 값입니다. (주민등록번호, 학번, 핸드폰 번호, 여권번호 같은 것)
  - React에서의 Key는 목록의 **아이템들을 구분하기 위한 고유한 문자열**입니다.

## 여러 개의 Component 렌더링하기 — `map()`

`map()` 함수로 다수의 Component(또는 Element)를 한 번에 만들 수 있습니다.

```jsx
const doubled = numbers.map((number) => number * 2);   // [2, 4, 6, 8, 10]
```

```jsx
const numbers = [1, 2, 3, 4, 5];
const listItems = numbers.map((number) =>
  <li>{number}</li>
);

ReactDOM.render(
  <ul>{listItems}</ul>,
  document.getElementById('root')
);

// 최종적으로 렌더링되는 코드는 아래와 같습니다.
ReactDOM.render(
  <ul>
    <li>{1}</li>
    <li>{2}</li>
    <li>{3}</li>
    <li>{4}</li>
    <li>{5}</li>
  </ul>,
  document.getElementById('root')
);
```

**별도의 리스트 Component로 분리하기**

```jsx
function NumberList(props) {
  const { numbers } = props;

  const listItems = numbers.map((number) =>
    <li>{number}</li>
  );

  return (
    <ul>{listItems}</ul>
  );
}

const numbers = [1, 2, 3, 4, 5];
ReactDOM.render(
  <NumberList numbers={numbers} />,
  document.getElementById('root')
);
```

이 예시를 실행하면 개발자 도구에 **경고 문구**가 나옵니다.

> `map()` 함수 안에 있는 Element에는 꼭 **key**가 필요하다

## List의 Key

Key의 값은 **같은 List에 있는 Element 사이에서만 고유**하면 됩니다.

```jsx
// 고유한 key 값 사용 — key로 숫자를 사용하는 경우(문자열로 바꿔서 지정)
const numbers = [1, 2, 3, 4, 5];
const listItems = numbers.map((number) =>
  <li key={number.toString()}>
    {number}
  </li>
);
```

```jsx
// 아이템의 고유한 ID가 있다면 그것을 key로 쓰는 것이 가장 좋습니다.
const todoItems = todos.map((todo) =>
  <li key={todo.id}>
    {todo.text}
  </li>
);

// 아이템들의 고유한 ID가 "없을 경우에만" 배열의 index를 사용합니다.
const todoItems = todos.map((todo, index) =>
  <li key={index}>
    {todo.text}
  </li>
);
```

- `map()` 함수 안에 있는 Element는 **꼭 key가 필요합니다.**

> **AI 코멘트**
>
> index를 key로 쓰면 안 되는 이유를 구체적으로 보면 이렇습니다. 목록 앞쪽에 항목을 추가하거나 순서를 바꾸면 **같은 key가 다른 항목을 가리키게 되어**, React가 "같은 항목이 갱신됐다"고 판단하고 내부 state를 그대로 둡니다. 그 결과 입력창의 값이나 체크 상태가 엉뚱한 행으로 따라가는 버그가 생깁니다.
>
> - key는 데이터에 붙은 **안정적이고 고유한 값**(DB의 id 등)이어야 합니다.
> - `Math.random()`처럼 렌더링마다 바뀌는 값은 매번 컴포넌트를 새로 만들어서 더 나쁩니다.
> - key는 React가 내부적으로만 쓰기 때문에 자식 컴포넌트의 `props.key`로는 받을 수 없습니다. 필요하면 `id` 같은 다른 이름의 props로 따로 넘깁니다.
> - 반환할 요소가 둘 이상이고 key가 필요하면 `<Fragment key={id}>`를 씁니다(짧은 `<>` 형태는 key를 받지 못합니다).
>
> key에는 "목록 항목을 구분한다"는 것 말고 쓰임이 하나 더 있습니다. **key를 바꾸면 React는 컴포넌트를 새로 만듭니다.** 이 프로젝트의 `GamePage`도 `key={game.gameId}`로 새 게임이 시작될 때 보드를 새로 만들고, 이 학습 페이지의 데모도 "다시 실행"을 누를 때 key를 바꿔 처음부터 다시 시작합니다.

## 이 챕터의 예제 (AttendanceBook)

**데모** 탭의 `AttendanceBook`은 `students` 배열(id, name)을 `map`으로 `<li>` 목록으로 만듭니다.

코드 탭을 보면 같은 목록을 만드는 방법이 **key 지정 방식별로** 주석으로 남아 있습니다.

1. `key` 없이 — 경고가 나타남
2. `key={student.id}` — 고유한 id를 사용 (권장)
3. `` key={`student-id-${student.id}`} `` — 포맷팅한 문자열로 key를 지정
4. `key={index}` — index를 key로 사용 (현재 실행되는 방식)

> **AI 코멘트**
>
> 이 데모가 마지막으로 `key={index}`를 쓰는 것은 목록이 고정되어 있고 추가·삭제·정렬이 없어서 문제가 생기지 않기 때문입니다. 이 프로젝트에서도 참가자·게임 목록처럼 항목이 늘고 줄어드는 곳은 `playerId`/`gameId`를 key로 쓰고, 읽기 전용으로 보여주기만 하는 오류 로그 목록(`LogList`)만 index를 씁니다.
