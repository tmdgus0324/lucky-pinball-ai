프로젝트를 만들고, 폴더 구조와 Gradle 명령, 설정 파일을 봅니다. 운영 업무에서는 남이 만든 프로젝트를 처음 열어 볼 일이 많아서, "어디에 무엇이 있나"를 아는 것이 중요합니다.

## 1. 프로젝트 만들기

[Spring Initializr](https://start.spring.io/)에서 아래처럼 고르고 Generate를 누르면 zip 파일이 내려옵니다. IntelliJ, VS Code에서도 같은 화면을 쓸 수 있습니다.

| 항목 | 고른 값 | 설명 |
|---|---|---|
| Project | Gradle - Groovy | 빌드 도구. Maven을 고르면 `pom.xml`이 생긴다 |
| Language | Java | |
| Spring Boot | 4.1.x | 정식 버전 중 가장 최신 |
| Group / Artifact | `com.example` / `reservation` | 패키지 이름과 프로젝트 이름이 된다 |
| Packaging | Jar | 실행 가능한 jar로 배포(1장) |
| Java | 17 | |
| Dependencies | Spring Web MVC | 필요한 starter를 고른다. 나중에 `build.gradle`에 추가해도 된다 |

## 2. 폴더 구조

코드 탭의 `structure.txt`에 전체 모양이 있습니다. 꼭 기억할 것은 세 가지입니다.

- 자바 코드는 `src/main/java`, 설정 파일은 `src/main/resources`, 테스트는 `src/test/java`에 둡니다.
- main 클래스는 가장 위 패키지에 둡니다. 그래야 아래 패키지의 클래스를 모두 찾습니다(1장).
- `resources/static`에 둔 파일은 주소 그대로 응답되고, `resources/templates`는 서버에서 HTML을 만들 때 씁니다(16장).

JSP 프로젝트의 `WebContent/WEB-INF/web.xml` 같은 설정 파일은 없습니다. 그 역할을 자동 설정과 `application.yml`이 대신합니다.

## 3. Gradle 명령

프로젝트 안의 `gradlew`(윈도우는 `gradlew.bat`)를 씁니다. Gradle을 따로 설치하지 않아도, 프로젝트에 적힌 버전의 Gradle을 내려받아 실행합니다. 그래서 팀원 모두가 같은 버전으로 빌드합니다.

| 명령 | 하는 일 | Maven이라면 |
|---|---|---|
| `./gradlew bootRun` | 빌드하고 바로 실행 | `mvn spring-boot:run` |
| `./gradlew test` | 테스트 실행 | `mvn test` |
| `./gradlew build` | 컴파일, 테스트, jar 만들기 | `mvn package` |
| `./gradlew bootJar` | 테스트 없이 실행 가능한 jar만 만들기 | |
| `./gradlew clean` | `build` 폴더 지우기 | `mvn clean` |

`build`는 테스트가 하나라도 실패하면 jar를 만들지 않습니다. 배포 전에는 `build`를 쓰는 것이 안전합니다.

## 4. application.yml

설정은 `src/main/resources/application.yml`(또는 `application.properties`)에 적습니다. 두 형식은 같은 뜻입니다.

```yaml
server:
  port: 8080
spring:
  application:
    name: reservation
```

```properties
server.port=8080
spring.application.name=reservation
```

yml은 들여쓰기로 계층을 나타냅니다. 탭 대신 공백을 쓰고, 같은 계층은 칸 수를 맞춰야 합니다. 들여쓰기가 틀리면 설정이 조용히 무시되거나 시작할 때 오류가 납니다.

자주 쓰는 설정:

| 설정 | 뜻 |
|---|---|
| `server.port` | 서버 포트(기본 8080) |
| `spring.application.name` | 애플리케이션 이름(로그 등에 쓰임) |
| `logging.level.패키지` | 패키지별 로그 레벨(15장) |

예제처럼 실행할 때 `--server.port=9090`을 주면 파일보다 이 값이 이깁니다. 우선순위는 4장에서 봅니다.

## 5. 시작 로그 읽기

코드 탭의 실행 결과를 위에서부터 읽으면 시작 순서가 보입니다.

1. `Starting ReservationApplication ... using Java 17`: 어떤 자바로 무엇을 시작하는지
2. `No active profile set`: 켜진 프로필(4장). 운영 서버라면 여기에 `prod` 같은 이름이 보여야 합니다
3. `Tomcat initialized with port 9090`: 내장 톰캣 준비
4. `Started ReservationApplication in 1.43 seconds`: 시작 완료. 이 줄이 보이면 요청을 받을 수 있습니다

장애가 나서 서버를 다시 띄웠을 때, `Started` 줄이 나왔는지와 포트·프로필이 맞는지부터 확인합니다.

## 6. 자주 만나는 시작 오류

| 증상 | 원인 | 해결 |
|---|---|---|
| `Web server failed to start. Port 8080 was already in use.` | 같은 포트를 다른 프로그램(이전에 띄운 서버 등)이 쓰고 있음 | 그 프로세스를 끄거나 포트를 바꾼다 |
| 서버는 떴는데 API가 404 | 컨트롤러가 main 클래스 패키지 밖에 있음 | 패키지 위치 확인(1장) |
| 로그의 한글이 깨짐 | 콘솔이나 JVM 인코딩 | 실행 옵션에 `-Dfile.encoding=UTF-8` |
| `Could not resolve placeholder` | 설정 파일에 없는 값을 코드가 찾음 | 설정 이름과 프로필 확인(4장) |

포트 충돌 메시지는 실제로 같은 포트로 서버를 두 번 띄워서 확인했습니다. 메시지 아래 Action에 "그 포트를 쓰는 프로세스를 찾아 끄거나 다른 포트를 쓰라"는 안내가 같이 나옵니다.

## 확인 문제

1. `./gradlew build`와 `./gradlew bootJar`는 무엇이 다른가요?
2. yml 파일에서 `logging.level.com.example.reservation: debug`는 어떤 뜻인가요?
3. 운영 서버를 다시 띄운 뒤 시작 로그에서 꼭 확인할 것 두 가지는 무엇인가요?
4. Gradle을 설치하지 않은 PC에서도 `./gradlew build`가 되는 이유는 무엇인가요?

## 정답

1. `build`는 테스트까지 돌리고 실패하면 jar를 만들지 않습니다. `bootJar`는 테스트 없이 jar만 만듭니다.
2. `com.example.reservation` 패키지와 그 아래 클래스의 로그를 DEBUG 레벨부터 출력합니다.
3. `Started ... in N seconds` 줄이 나왔는지, 그리고 포트와 프로필이 의도한 값인지입니다.
4. Gradle 래퍼(`gradlew`)가 프로젝트에 적힌 버전의 Gradle을 내려받아 실행하기 때문입니다.
