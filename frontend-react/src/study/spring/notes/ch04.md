코드에 값을 박아 두지 않고 설정 파일로 빼는 방법, 그리고 개발·운영 서버마다 설정을 다르게 쓰는 방법(프로필)을 봅니다. 운영 장애 중에는 "운영 서버가 엉뚱한 설정으로 떠 있었다"가 꽤 많습니다.

## 1. 왜 설정을 밖으로 빼나

DB 주소, 외부 API 주소, 정책 값(최대 예약 박수 등)은 환경마다 다르고 자주 바뀝니다. 코드에 적어 두면 값 하나 바꿀 때마다 다시 빌드해서 배포해야 합니다. 설정 파일이나 환경변수로 빼 두면 같은 jar를 그대로 두고 값만 바꿀 수 있습니다.

비밀번호와 API 키는 설정 파일에도 적지 않고 환경변수로만 넣습니다. 설정 파일은 git에 올라가기 때문입니다.

## 2. 값 하나 읽기: @Value

```java
public PolicyController(@Value("${spring.application.name:unknown}") String appName) { ... }
```

`${이름:기본값}` 형식입니다. 설정이 없으면 기본값을 쓰고, 기본값도 없으면 `Could not resolve placeholder` 오류로 서버가 뜨지 않습니다.

## 3. 값 여러 개 묶어 읽기: @ConfigurationProperties

관련된 설정이 여러 개면 클래스 하나로 묶는 편이 낫습니다.

```yaml
reservation:
  max-nights: 14
  checkin-time: "15:00"
```

```java
@ConfigurationProperties(prefix = "reservation")
public record ReservationProperties(int maxNights, LocalTime checkinTime, String notice) {}
```

- `max-nights`(yml)가 `maxNights`(자바)로 자동 연결됩니다.
- `"15:00"` 같은 글자는 필드 타입(`LocalTime`)에 맞게 바뀝니다.
- main 클래스에 `@ConfigurationPropertiesScan`을 붙여야 빈으로 등록됩니다.

| | `@Value` | `@ConfigurationProperties` |
|---|---|---|
| 쓰기 좋을 때 | 값 하나 | 관련 값 여러 개 |
| 설정이 없거나 이름이 틀리면 | 시작할 때 오류(기본값이 없을 때) | 오류 없이 빈 값(null, 0)으로 남음 |
| 타입 변환 | 됨 | 됨, 중첩 구조도 됨 |

## 4. 프로필: 환경마다 다른 설정

파일 이름 뒤에 `-프로필이름`을 붙입니다.

| 파일 | 언제 읽나 |
|---|---|
| `application.yml` | 항상 |
| `application-dev.yml` | dev 프로필이 켜졌을 때 |
| `application-prod.yml` | prod 프로필이 켜졌을 때 |

같은 이름의 값이 있으면 프로필 파일이 이깁니다. 프로필 파일에 없는 값은 `application.yml` 값을 그대로 씁니다. 실행 결과의 2번에서 `maxNights`는 prod 파일 값(7), `notice`는 공통 파일 값입니다.

프로필을 켜는 방법:

```bash
java -jar reservation.jar --spring.profiles.active=prod   # 실행 인자
SPRING_PROFILES_ACTIVE=prod java -jar reservation.jar     # 환경변수
```

시작 로그의 `The following 1 profile is active: "prod"`에서 켜진 프로필을 확인합니다. 운영 서버를 띄운 뒤 이 줄이 `dev`이거나 `No active profile set`이면 설정을 잘못 읽고 있는 것입니다.

## 5. 값의 우선순위

같은 설정이 여러 곳에 있으면 뒤에 있는 것이 이깁니다(자주 쓰는 것만 추림).

1. `application.yml`
2. `application-{프로필}.yml`
3. jar 밖의 설정 파일(jar와 같은 폴더의 `application.yml`, `config/` 폴더)
4. OS 환경변수
5. 명령줄 인자(`--이름=값`)

실행 결과의 3, 4번이 이 순서를 보여 줍니다. 환경변수(3)보다 명령줄 인자(5)가 이겼습니다.

운영에서는 jar 밖 설정 파일과 환경변수를 많이 씁니다. "코드에는 8080인데 왜 9090으로 떴지?" 같은 상황은 대부분 이 중 하나가 덮어쓴 것입니다.

## 6. 환경변수 이름 바꾸는 규칙

환경변수 이름에는 점(.)과 대시(-)를 쓰기 어렵습니다. 공식 문서의 규칙은 이렇습니다.

1. 점을 밑줄로 바꾼다
2. 대시는 뺀다
3. 대문자로 바꾼다

`reservation.max-nights` → `RESERVATION_MAXNIGHTS`, `spring.profiles.active` → `SPRING_PROFILES_ACTIVE`

## 확인 문제

1. `application.yml`에 `max-nights: 14`, `application-prod.yml`에 `max-nights: 7`이 있습니다. prod로 띄우면 값은?
2. 위 상황에서 `--reservation.max-nights=10`을 주고 prod로 띄우면 값은?
3. `spring.datasource.password`를 환경변수로 넣으려면 이름을 어떻게 쓰나요?
4. 운영 서버를 띄운 뒤 시작 로그에 `No active profile set, falling back to 1 default profile: "default"`가 보입니다. 무엇이 문제일 수 있나요?
5. DB 비밀번호를 `application-prod.yml`에 적으면 안 되는 이유는?

## 정답

1. 7. 프로필 파일이 공통 파일을 이깁니다.
2. 10. 명령줄 인자가 가장 우선입니다.
3. `SPRING_DATASOURCE_PASSWORD`
4. 프로필을 지정하지 않아서 prod 설정(운영 DB 주소 등)을 읽지 않았을 수 있습니다. 실행 스크립트의 `--spring.profiles.active`나 환경변수를 확인합니다.
5. 설정 파일은 git 저장소에 올라가서 코드를 볼 수 있는 모든 사람에게 비밀번호가 노출됩니다. 환경변수나 별도 비밀 저장소로 넣습니다.
