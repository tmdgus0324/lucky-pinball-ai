국내 SI·SM 시스템은 MyBatis와 Oracle 조합이 아직 가장 많습니다. 운영 업무에서는 "이 화면의 데이터가 이상하다"는 문의를 받고 SQL을 찾아 고치는 일이 가장 많습니다. 이번 장은 MyBatis로 SQL을 쓰고, 실행된 SQL을 로그에서 확인하는 방법을 봅니다.

## 1. MyBatis란

SQL을 직접 쓰고, 그 결과를 자바 객체에 담아 주는 도구입니다. JDBC로 직접 하면 이런 일을 매번 해야 합니다.

```java
Connection conn = dataSource.getConnection();
PreparedStatement ps = conn.prepareStatement("SELECT ... WHERE id = ?");
ps.setLong(1, id);
ResultSet rs = ps.executeQuery();
while (rs.next()) { r.setGuestName(rs.getString("guest_name")); ... }
// close 3번
```

MyBatis를 쓰면 SQL은 XML에 쓰고, 연결·실행·결과 담기·닫기는 MyBatis가 합니다.

## 2. 구성 세 가지

| 파일 | 하는 일 |
|---|---|
| Mapper 인터페이스(`ReservationMapper.java`) | 자바에서 부를 메서드. `@Mapper`를 붙이면 구현체를 MyBatis가 만든다 |
| Mapper XML(`ReservationMapper.xml`) | 실제 SQL. `namespace`는 인터페이스 전체 이름, 각 SQL의 `id`는 메서드 이름 |
| `application.yml` | XML 위치(`mybatis.mapper-locations`)와 설정 |

```java
@Mapper
public interface ReservationMapper {
    Reservation findById(Long id);
}
```

```xml
<mapper namespace="com.example.reservation.reservation.ReservationMapper">
    <select id="findById" resultType="...Reservation">
        SELECT ... FROM reservation WHERE id = #{id}
    </select>
</mapper>
```

운영 중 화면의 SQL을 찾을 때는 이 연결을 따라갑니다. 컨트롤러 → 서비스 → Mapper 메서드 이름 → 같은 이름의 XML `id`.

## 3. 결과 담기: resultType과 resultMap

| 방법 | 쓰는 때 |
|---|---|
| `resultType="클래스"` | 컬럼 이름과 필드 이름이 같을 때 |
| `resultMap="id"` | 이름이 다르거나, 조인 결과를 객체 여러 개로 나눠 담을 때 |

`map-underscore-to-camel-case: true`를 켜면 `guest_name` 컬럼이 `guestName` 필드로 자동 연결됩니다. 이 설정이 없는 레거시 프로젝트에서는 `SELECT guest_name AS guestName`처럼 별칭을 붙이거나 `resultMap`을 씁니다.

담을 객체는 기본 생성자와 setter가 있는 클래스를 많이 씁니다. 레거시 코드에서는 `ReservationVO`, `ReservationDTO` 같은 이름을 자주 봅니다.

## 4. #{}와 ${}

가장 중요한 내용입니다.

| | `#{}` | `${}` |
|---|---|---|
| 동작 | `?` 자리에 값을 따로 넣는다(PreparedStatement) | 값을 SQL 글자에 그대로 이어 붙인다 |
| 실행된 SQL | `WHERE guest_name = ?` | `WHERE guest_name = '김민수'` |
| 안전한가 | 안전 | 사용자 입력이면 SQL 주입 위험 |

실행 결과 마지막을 보세요. `${}`에 `' OR '1'='1`을 넣자 SQL이 `WHERE guest_name = '' OR '1'='1'`이 되어 모든 예약이 조회됐습니다. 같은 방법으로 데이터를 지우는 SQL까지 끼워 넣을 수 있습니다.

`${}`가 필요한 경우는 값이 아니라 SQL의 구조(컬럼 이름, 정렬 방향)를 바꿀 때뿐입니다. 이때도 사용자 입력을 그대로 넣지 않고, 허용한 값인지 먼저 확인합니다.

```java
// 정렬 컬럼은 정해진 것만 허용
String sort = Set.of("check_in", "guest_name").contains(input) ? input : "check_in";
```
```xml
ORDER BY ${sort}
```

운영 중인 코드에서 `${}`를 보면, 그 값이 사용자 입력에서 오는지부터 확인하세요. 보안 점검에서 가장 먼저 지적되는 부분입니다.

## 5. 동적 SQL

검색 화면처럼 조건이 있을 때만 WHERE에 붙여야 할 때 씁니다.

```xml
<select id="search" resultMap="reservationMap">
    SELECT ... FROM reservation
    <where>
        <if test="guestName != null and guestName != ''">
            AND guest_name LIKE '%' || #{guestName} || '%'
        </if>
        <if test="roomIds != null and roomIds.size() > 0">
            AND room_id IN
            <foreach collection="roomIds" item="roomId" open="(" separator="," close=")">
                #{roomId}
            </foreach>
        </if>
    </where>
</select>
```

| 태그 | 하는 일 |
|---|---|
| `<if test="조건">` | 조건이 참일 때만 안의 SQL을 붙인다 |
| `<where>` | 안에 내용이 있을 때만 WHERE를 붙이고, 맨 앞의 AND·OR를 지운다 |
| `<foreach>` | 목록을 `(?, ?, ?)`처럼 펼친다. IN 조건에 쓴다 |
| `<choose>`, `<when>`, `<otherwise>` | 자바의 switch처럼 하나만 고른다 |
| `<set>` | UPDATE에서 바뀐 컬럼만 SET에 넣고 끝의 쉼표를 지운다 |

XML 안에서 `<`, `>`는 태그로 읽히므로 `&lt;`, `&gt;`로 쓰거나 `<![CDATA[ ... ]]>`로 감쌉니다. 예제의 `check_in &gt;= #{from}`이 그 경우입니다.

`<foreach>`의 목록이 비어 있으면 `IN ()`이 되어 SQL 오류가 납니다. 예제처럼 `size() > 0` 조건으로 감싸 둡니다. Oracle은 IN 안에 1000개까지만 넣을 수 있다는 점도 기억해 두세요.

## 6. 실행된 SQL 보기

Mapper 패키지의 로그 레벨을 debug로 열면 실행된 SQL과 파라미터가 찍힙니다.

```yaml
logging:
  level:
    com.example.reservation.reservation: debug
```

```
==>  Preparing: SELECT ... WHERE room_id IN ( ? , ? ) AND status = ?
==> Parameters: 1(Long), 2(Long), CONFIRMED(String)
<==      Total: 2
```

`?`에 파라미터를 직접 채우면 DB 도구(DBeaver, SQL Developer)에서 같은 SQL을 실행해 볼 수 있습니다. "화면에 데이터가 안 나온다"는 문의는 대부분 이 방법으로 조건이 어떻게 만들어졌는지 확인하면서 풀립니다. 운영 서버는 로그가 많아지므로 확인할 때만 잠깐 debug로 올리고 다시 내립니다(15장).

## 7. 등록과 수정

```xml
<insert id="insert" useGeneratedKeys="true" keyProperty="id">
    INSERT INTO reservation (...) VALUES (#{roomId}, #{guestName}, ...)
</insert>
```

- `useGeneratedKeys`와 `keyProperty`: DB가 만든 키 값을 객체의 `id`에 다시 넣어 줍니다. Oracle 시퀀스를 쓰는 프로젝트는 `<selectKey>`로 시퀀스 값을 먼저 가져오는 방식을 많이 씁니다.
- `insert`, `update`, `delete` 메서드는 바뀐 줄 수를 돌려줍니다. 0이면 대상이 없었다는 뜻이라 404 같은 처리를 할 수 있습니다(예제의 cancel).
- 파라미터가 두 개 이상이면 `@Param("이름")`을 붙여 XML에서 `#{이름}`으로 씁니다.

## 확인 문제

1. Mapper 인터페이스의 `search` 메서드가 실행하는 SQL은 어디서 찾나요?
2. `#{}`와 `${}`의 차이를 실행된 SQL 모양으로 설명해 보세요.
3. 정렬 기준을 화면에서 받아 `ORDER BY ${sort}`로 쓰려고 합니다. 어떻게 해야 안전한가요?
4. 검색 조건이 하나도 없을 때 `WHERE AND ...`가 되지 않게 하는 태그는?
5. 운영에서 "검색 결과가 이상하다"는 문의가 왔습니다. MyBatis 프로젝트에서 실제 실행된 SQL을 확인하는 방법은?

## 정답

1. `namespace`가 `ReservationMapper`의 전체 이름인 XML 파일에서 `id="search"`인 SQL입니다.
2. `#{}`는 `WHERE guest_name = ?`처럼 물음표로 바뀌고 값은 따로 들어갑니다. `${}`는 `WHERE guest_name = '김민수'`처럼 값이 SQL 글자에 들어갑니다.
3. 허용할 컬럼 이름 목록을 정해 두고, 입력값이 목록에 있을 때만 쓰고 아니면 기본값을 씁니다.
4. `<where>`입니다. 안에 내용이 있을 때만 WHERE를 붙이고 맨 앞의 AND·OR를 지웁니다.
5. 해당 Mapper 패키지의 로그 레벨을 debug로 올려 `==> Preparing`, `==> Parameters` 로그를 봅니다. 파라미터를 채운 SQL을 DB 도구에서 직접 실행해 결과를 비교합니다.
