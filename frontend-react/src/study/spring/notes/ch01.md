Spring Boot가 무엇이고, JSP·WAS 환경과 무엇이 다른지 봅니다. 이번 공부 내내 키워 갈 예제 "객실 예약 API"의 첫 화면도 여기서 띄웁니다.

## 1. Spring과 Spring Boot

Spring은 자바 웹 애플리케이션을 만들 때 쓰는 프레임워크입니다. 객체를 대신 만들어 연결해 주고(3장), 웹 요청을 메서드에 연결해 주고(5~6장), DB 작업과 트랜잭션을 도와줍니다(10~12장).

예전 Spring은 이런 기능을 쓰려면 XML이나 설정 클래스를 많이 써야 했습니다. 어떤 라이브러리를 어떤 버전으로 넣을지도 직접 맞춰야 했습니다.

Spring Boot는 이 준비 작업을 줄여 주는 도구입니다. 하는 일은 크게 세 가지입니다.

| 기능 | 하는 일 |
|---|---|
| 자동 설정 | 넣은 라이브러리를 보고 필요한 설정을 알아서 해 준다 |
| starter | 한 줄만 추가하면 필요한 라이브러리 묶음이 들어온다 |
| 내장 서버 | 톰캣이 jar 안에 들어 있어서 `java -jar`로 바로 실행된다 |

Spring Boot는 Spring을 대신하는 것이 아니라 Spring을 쉽게 쓰게 해 주는 것입니다. 코드에서 쓰는 `@RestController`, `@Service`, `@Transactional`은 모두 Spring의 기능입니다.

## 2. 자동 설정

자동 설정은 "클래스패스에 어떤 라이브러리가 있는지"를 보고 설정을 정합니다.

- `spring-boot-starter-webmvc`가 있으면 톰캣과 Spring MVC를 설정합니다.
- DB 드라이버(H2, Oracle 등)가 있고 직접 만든 DataSource가 없으면 DataSource를 만듭니다.
- 직접 같은 종류의 설정을 만들면 자동 설정은 물러납니다. 자동 설정은 기본값일 뿐 강제가 아닙니다.

어떤 자동 설정이 적용됐는지 보고 싶으면 `--debug`를 붙여 실행합니다. 적용된 것과 적용되지 않은 것, 그 이유가 로그에 나옵니다.

```bash
java -jar build/libs/reservation-0.0.1-SNAPSHOT.jar --debug
```

특정 자동 설정을 끄고 싶으면 `exclude`를 씁니다.

```java
@SpringBootApplication(exclude = DataSourceAutoConfiguration.class)
```

## 3. starter와 버전 관리

starter는 자주 같이 쓰는 라이브러리를 묶어 놓은 의존성입니다. 공식 starter는 `spring-boot-starter-*` 형식의 이름을 씁니다.

```gradle
implementation 'org.springframework.boot:spring-boot-starter-webmvc'
```

이 한 줄로 Spring MVC, 내장 톰캣, JSON 변환(Jackson)이 들어옵니다. 버전을 적지 않는 것이 보통입니다. Spring Boot가 서로 맞는 버전 목록을 관리하고 있어서, Spring Boot 버전만 올리면 나머지도 맞춰서 올라갑니다.

Spring Boot 4부터 웹 starter 이름이 `spring-boot-starter-web`에서 `spring-boot-starter-webmvc`로 바뀌었습니다. 인터넷 자료는 대부분 예전 이름을 쓰니 버전을 확인하세요.

## 4. 내장 톰캣과 실행 가능한 jar

JSP 프로젝트에서는 보통 이렇게 배포합니다.

1. 프로젝트를 war 파일로 만든다
2. 서버에 설치된 WAS(톰캣, JEUS, WebLogic 등)에 war를 올린다
3. WAS를 재시작한다

Spring Boot는 톰캣이 애플리케이션 안에 들어 있습니다. 빌드하면 실행 가능한 jar 하나가 나오고, 이 jar에는 우리 코드와 모든 라이브러리, 톰캣이 함께 들어 있습니다.

```bash
./gradlew bootJar                                     # build/libs/*.jar 생성
java -jar build/libs/reservation-0.0.1-SNAPSHOT.jar   # 서버 시작
```

서버에 자바만 있으면 되고 WAS를 따로 설치하지 않습니다. 운영 서버에서 프로세스를 내리고 새 jar로 다시 띄우는 것이 배포입니다(15장).

개발 중에는 jar를 만들지 않고 `./gradlew bootRun`으로 바로 실행해도 됩니다.

## 5. @SpringBootApplication

main 메서드가 있는 클래스에 붙이는 애너테이션입니다. 세 가지를 합친 것입니다.

| 포함된 것 | 하는 일 |
|---|---|
| `@SpringBootConfiguration` | 이 클래스가 설정 클래스라는 표시 |
| `@EnableAutoConfiguration` | 자동 설정 켜기 |
| `@ComponentScan` | 이 클래스가 있는 패키지와 그 아래 패키지에서 `@Component`류 클래스 찾기 |

`@ComponentScan` 때문에 **main 클래스는 가장 위 패키지에 둡니다.** 예제는 `com.example.reservation`에 두었으니, 앞으로 만들 `com.example.reservation.room` 같은 하위 패키지의 클래스도 모두 찾습니다. main 클래스보다 위나 옆 패키지에 둔 클래스는 찾지 못합니다.

이번 공부는 챕터마다 따로 예제를 만들지 않고, 리조트 객실 예약 API 하나를 1장부터 계속 키웁니다.

| 1~4 | 프로젝트 뼈대, 서비스 분리, 설정값 |

| 14~17 | 외부 결제 API 호출, 로그와 운영, 화면, 테스트 |

1. Spring과 Spring Boot의 관계를 한 문장으로 설명해 보세요.

3. main 클래스를 `com.example.reservation.app` 패키지로 옮기면, `com.example.reservation` 패키지의 `RoomController`는 어떻게 될까요?
4. 운영 서버에 WAS 없이 배포하려면 서버에 무엇이 있어야 하나요?

## 정답

1. Spring Boot는 Spring을 대신하는 것이 아니라, 자동 설정·starter·내장 서버로 Spring을 쉽게 쓰게 해 주는 도구입니다.
2. starter에 내장 톰캣이 들어 있고, 실행 가능한 jar 안에 함께 포함되기 때문입니다.
3. 컴포넌트 스캔 범위(`com.example.reservation.app` 아래) 밖이라 등록되지 않습니다. `/rooms`를 호출하면 404가 납니다.
4. 자바(JRE)만 있으면 됩니다. `java -jar`로 실행합니다.
