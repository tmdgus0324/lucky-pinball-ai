핀볼 게임은 서버에서 화면을 만들지 않습니다. 백엔드는 `@RestController`로 JSON만 돌려주고, 화면은 따로 배포한 React가 그립니다. 그래서 이번 장은 "이 프로젝트를 서버 화면 방식으로 만들었다면"을 기준으로 비교합니다.

## 백엔드의 빈 templates 폴더

`backend/src/main/resources/` 아래에 `templates/`와 `static/` 폴더가 있지만 비어 있습니다. 프로젝트를 만들 때 생긴 폴더입니다. Thymeleaf를 의존성에 넣으면 `templates/`에 `.html`을, 이미지·CSS 같은 정적 파일은 `static/`에 둡니다.

## 화면을 따로 둔 결과

API + 프론트 방식을 고른 대신 서버 화면 방식이라면 없었을 일들이 생겼습니다.

| 생긴 일 | 장 |
|---|---|
| 화면과 서버 주소가 달라서 CORS 설정이 필요했다 | 5장 |
| 같은 이유로 쿠키 세션이 복잡해서 관리자 로그인을 토큰으로 했다 | 9장 |
| 오류 응답 모양(`{"error","traceId"}`)을 정해서 프론트와 맞췄다 | 8장 |
| 배포가 두 곳(Render, Vercel)이다 | 15장 |

핀볼은 공이 움직이는 게임 화면이 중심이라 브라우저에서 그리는 방식이 맞았습니다. 반대로 표와 조회 위주인 관리자 화면만 있는 시스템이었다면 Thymeleaf 하나로 더 단순하게 만들 수 있었습니다.

## 관리자 화면을 Thymeleaf로 만든다면

지금의 관리자 참가자 목록은 JSON을 주고 React가 표를 그립니다.

```java
// admin/AdminController.java (지금, @RestController)
@GetMapping("/api/admin/players")
public List<PlayerAdminView> players() { ... }
```

서버 화면 방식이면 이렇게 됩니다(실제 코드에는 없는 예시입니다). 목록을 만드는 부분은 같고, 반환만 달라집니다.

```java
// @Controller
@GetMapping("/admin/players")
public String players(Model model) {
    model.addAttribute("players", /* 지금 players()가 만드는 List<PlayerAdminView> */);
    return "admin-players";            // templates/admin-players.html
}
```

```html
<tr th:each="p : ${players}">
  <td th:text="${p.name}">이름</td>
  <td th:text="${p.birthDate} ?: '미입력'">생년월일</td>
</tr>
```

로그인도 같은 주소(도메인)라서 9장의 세션 방식을 그대로 쓸 수 있습니다.

## 이스케이프는 어디서나 같은 문제

정리 6절의 이스케이프는 화면 기술과 상관없이 챙겨야 합니다. 핀볼의 두 화면 버전을 보면 차이가 잘 보입니다.

| 버전 | 사용자 입력 출력 | 이스케이프 |
|---|---|---|
| React(`frontend-react`) | `{player.name}` | 자동(Thymeleaf의 `th:text`와 같음) |
| 처음 만든 순수 JS(`frontend`) | `innerHTML` 문자열에 넣음 | 직접 `escapeHtml()`로 처리(JSP의 `c:out`과 같음) |

```js
// frontend/js/admin.js
return `<tr><td>${player.playerId}</td><td>${escapeHtml(player.name)}</td>...</tr>`;
```

순수 JS 버전은 참가자 이름을 `innerHTML`에 넣기 때문에, 이름에 태그를 넣으면 스크립트가 실행될 수 있었습니다. 그래서 이름처럼 사용자가 입력한 값만 골라 이스케이프했습니다. JSP에서 `${...}`를 그대로 쓰는 코드를 고칠 때와 같은 일입니다.
