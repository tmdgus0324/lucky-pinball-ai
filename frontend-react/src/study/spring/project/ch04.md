핀볼 게임 백엔드는 프로필 파일을 따로 두지 않고, `application.yml` 하나에 기본값을 적고 운영 값은 환경변수로 덮어씁니다.

## 기본값 + 환경변수

```yaml
server:
  port: ${PORT:8080}

spring:
  datasource:
    url: jdbc:h2:file:./data/luckypinball;AUTO_SERVER=TRUE
    username: sa
    password:

admin:
  username: ${ADMIN_USERNAME:admin}
  password: ${ADMIN_PASSWORD:}

rate-limit:
  client-ip-header: ${CLIENT_IP_HEADER:True-Client-IP}
```

운영 서버(Render)에는 아래 환경변수를 넣었습니다. 값은 코드와 git에 없습니다.

| 환경변수 | 덮어쓰는 설정 |
|---|---|
| `PORT` | `server.port` |
| `SPRING_DATASOURCE_URL`, `_USERNAME`, `_PASSWORD` | `spring.datasource.*` (운영 DB 주소와 계정) |
| `ANTHROPIC_API_KEY` | Claude API 키 |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | 관리자 계정 |

`SPRING_DATASOURCE_URL`은 yml에 `${...}`로 적지 않았는데도 반영됩니다. 환경변수가 설정 파일보다 우선하기 때문입니다(정리 5절).

## 비밀번호 기본값을 비워 둔 이유

```yaml
admin:
  password: ${ADMIN_PASSWORD:}
```

기본값을 `admin123` 같은 값으로 두면, 운영에 환경변수를 깜빡 안 넣었을 때 누구나 그 비밀번호로 들어올 수 있습니다. 그래서 기본값을 비워 두고, 비밀번호가 비어 있으면 로그인을 항상 거절하게 했습니다. 설정을 빠뜨리면 "안 되는 쪽"으로 실패하게 만든 것입니다.

## @Value로 받는 예

```java
public FortuneQueryService(...,
        @Value("${fortune.fallback-enabled:true}") boolean fallbackEnabled) { ... }
```

Claude 호출이 실패했을 때 임시 점수로 대신할지를 설정으로 끄고 켤 수 있게 했습니다. 설정이 없으면 기본값 `true`입니다.
