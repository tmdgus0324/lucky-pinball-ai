핀볼 게임 백엔드에서 람다식, Stream, Optional이 쓰인 곳입니다. 정리에서 본 모양이 그대로 나옵니다.

## groupingBy: 참가자별 운세 이력 묶기

```java
// fortune/FortuneResultJpaRepository.java
// groupingBy는 키가 null이면 예외를 던지므로, playerId가 없는 행은 뺀다.
default Map<Long, List<FortuneResultEntity>> findAllGroupedByPlayerId() {
    return findAllByOrderByCreatedDateAscIdAsc().stream()
            .filter(result -> result.getPlayerId() != null)
            .collect(Collectors.groupingBy(FortuneResultEntity::getPlayerId));
}
```

13장의 N+1을 고친 코드입니다. 참가자마다 이력을 조회하던 것을, 이력을 한 번에 가져와서 자바에서 참가자별로 묶었습니다. 정리 8절의 "키가 null이면 예외"를 미리 피하려고 `filter`를 앞에 두었습니다.

## Supplier: 잠금 안에서 실행할 동작 넘기기

```java
// common/KeyedLock.java
public <T> T withLock(K key, Supplier<T> action) {
    ...
    entry.lock.lock();
    try {
        return action.get();       // 넘겨받은 동작을 잠금 안에서 실행
    } finally {
        entry.lock.unlock();
        ...
    }
}

// fortune/FortuneQueryService.java
return identityLocks.withLock(new Identity(player.getName(), player.getBirthDate()),
        () -> resolveForIdentity(player, playerId, reuseOwnFallback));
```

같은 사람(이름+생년월일)의 운세 요청이 동시에 오면 Claude를 한 번만 부르게 하는 잠금입니다. "잠그고, 실행하고, 풀기"는 공통이고 "무엇을 실행할지"만 매번 다르기 때문에, 그 부분을 람다(`Supplier`)로 받습니다. 정리 1절의 "메서드에 동작을 넘긴다"를 직접 만든 예입니다.

## mapToInt와 OptionalInt: 최고 점수 구하기

```java
// game/GameService.java
OptionalInt maxScore = participants.stream()
        .filter(p -> p.fortuneScore() != null)
        .mapToInt(GameParticipant::fortuneScore)
        .max();
if (maxScore.isEmpty()) {
    return participants; // 아무도 실제 점수가 없으면 그대로 둔다
}
```

참가자 전원이 생년월일을 넣지 않으면 점수가 하나도 없습니다. 그래서 `max()`는 숫자가 아니라 "없을 수도 있는 숫자"(`OptionalInt`)를 돌려줍니다.

## toMap: 키가 겹치지 않을 때만

```java
// game/GameService.java
Map<Long, String> namesByPlayerId = session.getParticipants().stream()
        .collect(Collectors.toMap(GameParticipant::playerId, GameParticipant::name));
```

참가자 번호로 이름을 찾는 표입니다. 한 판 안에서 참가자 번호는 겹치지 않아서 합치는 방법 없이 `toMap`을 썼습니다. 이름을 키로 했다면 같은 이름이 둘일 때 정리 8절의 `Duplicate key` 예외가 납니다.

실제로 게임 화면(프론트)의 실시간 순위 패널은 처음에 이름을 키로 썼습니다. 같은 이름의 참가자가 둘이면 순위 패널에서 한 명이 사라지는 문제가 있어서 참가자 번호로 바꿨습니다(devhelp/10). 자바의 `toMap`은 키가 겹치면 예외를 내지만, 자바스크립트의 `Map`은 조용히 덮어써서 더 늦게 발견됐습니다.

## Optional: 없으면 예외, 없으면 새로

```java
// player/PlayerService.java
.orElseThrow(() -> ApiException.notFound("Player not found: " + playerId));

// game/JpaGameRepository.java
.orElseGet(() -> new GameEntity(session.getGameId(), session.getCreatedAt()));

// common/GlobalExceptionHandler.java
String message = ex.getBindingResult().getFieldErrors().stream()
        .findFirst()
        .map(fieldError -> fieldError.getField() + " " + fieldError.getDefaultMessage())
        .orElse("Invalid request");
```

- `orElseThrow`: 없는 참가자면 404 예외(8장).
- `orElseGet`: 저장된 게임이 없으면 새로 만든다. 정리 9절처럼 값이 있을 때는 `new GameEntity(...)`를 실행하지 않는다.
- `findFirst().map(...).orElse(...)`: 검증 오류(7장) 중 첫 번째만 골라 메시지로 만든다.
