핀볼 게임 백엔드의 참가자 등록 요청입니다.

## 규칙

```java
// player/PlayerController.java
public record RegisterPlayerRequest(
        // 길이 제한 없이 받으면 화면 레이아웃이 깨지고, Claude 프롬프트에도 그대로 들어간다.
        @NotBlank @Size(max = 20) String name,
        // 생년월일은 선택사항 — 없으면 버프 없이 참여(AI 호출 안 함). 입력하면 미래 날짜는 막는다.
        @Past LocalDate birthDate
) {}

@PostMapping("/api/player")
@ResponseStatus(HttpStatus.CREATED)
public PlayerResponse register(@Valid @RequestBody RegisterPlayerRequest request) { ... }
```

- 이름 길이를 20자로 막은 이유는 화면 때문만이 아닙니다. 이름이 Claude에게 보내는 글에 그대로 들어가서, 길게 받으면 AI 비용이 늘고 엉뚱한 지시를 끼워 넣을 여지도 커집니다.
- `birthDate`는 선택이라 `@NotNull` 없이 `@Past`만 붙였습니다. 값이 없으면(null) `@Past`는 검사하지 않습니다(정리 3절).

## 이 규칙이 처음엔 없었다

처음 만들 때는 `name`에 `@NotBlank`만 있었고 생년월일 검사도 없었습니다. 미래 날짜(2026-09-25)가 실제로 DB에 들어가 있는 것을 보고 `@Size`, `@Past`를 추가했습니다. 화면에서 막았다고 안심하면 안 되는 이유입니다.

## 직접 요청 탭

"직접 요청" 탭에서 이 규칙들을 실제로 어겨 볼 수 있습니다. 검증에 실패하면 컨트롤러가 실행되지 않으므로 데이터는 저장되지 않습니다. 응답 문구가 영어(`name must not be blank`)인 것은 정리 5절처럼 `message`를 따로 적지 않아서 서버 기본 언어를 따랐기 때문입니다.
