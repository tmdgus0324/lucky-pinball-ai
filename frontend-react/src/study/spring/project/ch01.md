핀볼 게임 백엔드(`01_LuckyPinballAI/backend`)에서 1장 내용이 실제로 어떻게 쓰였는지 봅니다.

## main 클래스

`com.luckypinball` 패키지 맨 위에 있고, 그 아래에 `player`, `fortune`, `game`, `admin`, `common`, `config` 패키지가 있습니다. 컴포넌트 스캔이 이 패키지들을 모두 찾습니다.

```java
// backend/src/main/java/com/luckypinball/LuckyPinballApplication.java
@SpringBootApplication
public class LuckyPinballApplication {

    public static void main(String[] args) {
        SpringApplication.run(LuckyPinballApplication.class, args);
    }
}
```

## starter

`build.gradle`의 Spring 의존성에는 버전이 없습니다. 버전을 적은 것은 Spring Boot가 관리하지 않는 Claude SDK 하나뿐입니다.

```gradle
implementation 'org.springframework.boot:spring-boot-starter-webmvc'
implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
implementation 'org.springframework.boot:spring-boot-starter-validation'
implementation 'com.anthropic:anthropic-java:2.34.0'   // Spring Boot가 관리하지 않아서 버전을 적음
runtimeOnly 'com.h2database:h2'
runtimeOnly 'org.postgresql:postgresql'
```

## 자동 설정이 DB를 고르는 방법

H2와 PostgreSQL 드라이버가 둘 다 들어 있습니다. `application.yml`에는 드라이버 이름을 적지 않고 DB 주소만 적었습니다.

```yaml
spring:
  datasource:
    url: jdbc:h2:file:./data/luckypinball;AUTO_SERVER=TRUE
```

- 로컬에서는 이 주소(`jdbc:h2:`)를 보고 H2를 씁니다.
- 운영(Render)에서는 환경변수 `SPRING_DATASOURCE_URL`에 `jdbc:postgresql:...`을 넣어서 PostgreSQL을 씁니다.

자동 설정이 주소 앞부분을 보고 맞는 드라이버를 고르기 때문에, 코드와 설정 파일을 고치지 않고 DB를 바꿨습니다. 설정값과 환경변수는 4장에서 자세히 봅니다.

## 실행 가능한 jar로 배포

운영 서버(Render)는 Docker로 jar를 만들고 `java -jar`로 실행합니다. WAS를 설치하지 않습니다.

```dockerfile
# backend/Dockerfile
# 1단계: JDK로 jar 만들기
FROM eclipse-temurin:17-jdk AS build
WORKDIR /app
COPY . .
RUN chmod +x gradlew && ./gradlew --no-daemon bootJar

# 2단계: JRE만 있는 가벼운 이미지에서 실행
FROM eclipse-temurin:17-jre
WORKDIR /app
COPY --from=build /app/build/libs/*.jar app.jar
ENTRYPOINT ["java", "-Dfile.encoding=UTF-8", "-jar", "app.jar"]
```

`-Dfile.encoding=UTF-8`은 한글 로그가 깨지지 않게 하려고 넣었습니다. 배포와 로그는 15장에서 다룹니다.
