핀볼 게임 백엔드가 부르는 외부 API는 Claude(운세 생성) 하나입니다. 이번 장의 내용이 거의 다 들어 있습니다.

## 기본 타임아웃을 확인하고 줄였다

Claude SDK는 RestClient 대신 자체 HTTP 클라이언트(OkHttp)를 쓰지만, 챙길 것은 같습니다. SDK 기본값을 먼저 확인했더니 타임아웃 10분, 재시도 2회였습니다. Claude가 응답하지 않으면 사용자 한 명의 운세 요청이 최대 30분 가까이 묶일 수 있는 값입니다.

```java
// fortune/ClaudeFortuneGenerator.java
public ClaudeFortuneGenerator(@Value("${anthropic.timeout-seconds:10}") long timeoutSeconds,
                              @Value("${anthropic.max-retries:1}") int maxRetries) { ... }

client = AnthropicOkHttpClient.builder().fromEnv()
        .timeout(timeout)          // 10초
        .maxRetries(maxRetries)    // 1회
        .build();
```

타임아웃과 재시도 횟수는 설정값(4장)이라 다시 빌드하지 않고 바꿀 수 있습니다.

## 실패해도 게임은 계속된다

Claude 호출이 실패하면(시간 초과, 5xx 등) 오류를 내는 대신 규칙으로 만든 임시 점수로 게임을 진행합니다. 정리 3절의 "실패 종류별 대응"을 화면 쪽으로 풀어낸 것입니다. 임시 점수는 캐시에 넣지 않아서, Claude가 복구되면 다음 요청부터 진짜 결과를 받습니다.

## 실패 종류를 나눠서 보여 준다

관리자 화면의 "AI 연결 확인"은 Claude를 아주 짧게 한 번 불러 보고, 실패하면 원인을 나눠서 보여 줍니다.

| 결과 | 뜻 | 조치 |
|---|---|---|
| `KEY_MISSING` | API 키 환경변수가 없음 | 운영 환경변수 확인 |
| `AUTH_FAILED` | 키가 틀렸거나 폐기됨(401) | 새 키로 교체 |
| `CREDIT_EXHAUSTED` | 크레딧 부족 | 충전 |
| `RATE_LIMITED` | 요청 한도 초과(429) | 잠시 뒤 다시 |
| `TIMEOUT` | 응답 시간 초과 | 대개 일시적 |
| `UNREACHABLE` | 연결 실패 | 네트워크·상대 서버 장애 |
| `UPSTREAM_ERROR` | 상대 서버 5xx | 대개 일시적 |

운영 중 "AI가 안 된다"는 문의가 오면 이 버튼 하나로 어디 문제인지 바로 알 수 있습니다.

## 장애를 일부러 만들어서 테스트했다

정리 5절의 교훈처럼, 실패 처리는 실제로 실패를 만들어야 확인됩니다. 테스트에서 JDK의 `HttpServer`로 가짜 Claude 서버를 띄우고, 일부러 늦게 응답하거나 401·429·500을 돌려주거나 연결을 끊게 해서 위 분류가 맞게 나오는지 확인했습니다(17장).

그 과정에서 실제 버그도 찾았습니다. 한동안 쓰지 않은 연결을 재사용하다가 끊긴 연결 오류가 나면, 그것을 "연결 불가(UNREACHABLE)"로 잘못 보여 주고 있었습니다. 이런 경우는 한 번 다시 시도하도록 고쳤습니다(devhelp/09).
