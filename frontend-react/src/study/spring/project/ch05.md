핀볼 게임 백엔드는 필터 세 개를 씁니다. 인터셉터는 쓰지 않았습니다.

## 필터 세 개와 순서

```
요청 → TraceIdFilter → RateLimitFilter → AdminAuthFilter → DispatcherServlet → 컨트롤러
```

| 필터 | 하는 일 | 막을 때 |
|---|---|---|
| `TraceIdFilter` | 요청마다 8자리 추적 ID를 만들어 로그와 응답 헤더에 붙인다 | 막지 않음 |
| `RateLimitFilter` | 같은 IP의 요청 횟수를 센다(운세 분당 20회, 로그인 분당 10회) | 429 |
| `AdminAuthFilter` | `/api/admin/**`에 로그인 토큰이 있는지 확인한다 | 401 |

`TraceIdFilter`에는 `@Order(Ordered.HIGHEST_PRECEDENCE)`를 붙여 가장 먼저 실행되게 했습니다. 다른 필터가 막아서 응답하는 경우에도 그 로그에 추적 ID가 찍혀야 하기 때문입니다.

## 정리 3절의 try/finally를 실제로 쓴 곳

```java
// common/TraceIdFilter.java
protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain chain)
        throws ServletException, IOException {
    String traceId = TraceId.newId();
    MDC.put(TraceId.MDC_KEY, traceId);
    response.setHeader(TraceId.HEADER, traceId);

    long startedAt = System.currentTimeMillis();
    try {
        chain.doFilter(request, response);
    } finally {
        log.info("{} {} -> {} ({}ms)", request.getMethod(), request.getRequestURI(),
                response.getStatus(), System.currentTimeMillis() - startedAt);
        // 톰캣 스레드는 재사용되므로 반드시 비워야 다음 요청에 이전 ID가 새어 나가지 않는다.
        MDC.remove(TraceId.MDC_KEY);
    }
}
```

`finally`에 둔 이유가 두 가지입니다. 예외가 나도 요청 로그가 남아야 하고, 무엇보다 `MDC.remove`가 꼭 실행되어야 합니다. 톰캣은 스레드를 재사용하기 때문에, 지우지 않으면 다음 요청 로그에 이전 요청의 추적 ID가 찍힙니다.

## 필터가 막은 응답에서 생긴 버그

필터가 직접 401·429를 응답하면 DispatcherServlet을 거치지 않습니다. 그래서 스프링 MVC에 해 둔 CORS 설정이 적용되지 않아, 브라우저에서 응답 대신 "Failed to fetch" 오류만 보이는 버그가 있었습니다. 필터에서 응답할 때 CORS 헤더를 직접 붙여서 고쳤습니다(`CorsSupport`). 필터는 스프링 MVC 바깥이라는 점을 보여 주는 사례입니다.
