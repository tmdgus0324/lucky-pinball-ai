$ java StreamOrder.java
== A. filter → map → toList ==
1번 김민수 꺼냄
  filter 확정? 통과
  map → 김민수
2번 박지영 꺼냄
  filter 확정? 걸러짐
3번 이수진 꺼냄
  filter 확정? 통과
  map → 이수진
4번 최현우 꺼냄
  filter 확정? 통과
  map → 최현우
5번 정다은 꺼냄
  filter 확정? 걸러짐
6번 한지민 꺼냄
  filter 확정? 통과
  map → 한지민
결과 [김민수, 이수진, 최현우, 한지민]
# filter를 6번 다 하고 나서 map을 하는 것이 아니다. 요소 하나가 filter → map을 끝까지 지나간 뒤 다음 요소를 꺼낸다.

== B. filter → map → limit(2) → toList ==
1번 김민수 꺼냄
  filter 2박 이상? 통과
  map → 김민수
2번 박지영 꺼냄
  filter 2박 이상? 걸러짐
3번 이수진 꺼냄
  filter 2박 이상? 통과
  map → 이수진
결과 [김민수, 이수진]
# 2개가 차자 멈췄다. 4~6번은 꺼내지도 않았다.

== C. sorted → map → toList ==
1번 김민수 꺼냄 → sorted가 모아 둠
2번 박지영 꺼냄 → sorted가 모아 둠
3번 이수진 꺼냄 → sorted가 모아 둠
4번 최현우 꺼냄 → sorted가 모아 둠
5번 정다은 꺼냄 → sorted가 모아 둠
6번 한지민 꺼냄 → sorted가 모아 둠
  map → 박지영(1박)
  map → 한지민(1박)
  map → 김민수(2박)
  map → 최현우(2박)
  map → 이수진(3박)
  map → 정다은(4박)
결과 [박지영, 한지민, 김민수, 최현우, 이수진, 정다은]
# sorted는 전부 받아야 순서를 정할 수 있어서, 여기서는 6개를 모두 모은 뒤에야 map이 시작됐다.

== D. groupingBy(객실, counting) ==
1번 김민수 꺼냄 → 오션뷰 칸 +1
2번 박지영 꺼냄 → 스탠다드 칸 +1
3번 이수진 꺼냄 → 오션뷰 칸 +1
4번 최현우 꺼냄 → 스위트 칸 +1
5번 정다은 꺼냄 → 오션뷰 칸 +1
6번 한지민 꺼냄 → 스탠다드 칸 +1
결과 {오션뷰=3, 스탠다드=2, 스위트=1}


$ java OptionalBasics.java
== 1. 값 꺼내기 ==
1번 있음?        true
9번 있음?        false
1번 이름(map)    김민수
9번 이름(map)    없음
2번이 있으면 실행 박지영

== 2. orElse와 orElseGet의 차이 ==
orElse, 값 있음
    (defaultName() 실행됨)
  결과 김민수
orElseGet, 값 있음
  결과 김민수
orElseGet, 값 없음
    (defaultName() 실행됨)
  결과 손님
# orElse(defaultName())은 값이 있어도 defaultName()을 먼저 실행한다(인자를 먼저 계산하기 때문).
# orElseGet은 값이 없을 때만 실행한다. 기본값을 만드는 데 DB 조회 같은 비용이 들면 orElseGet을 쓴다.

== 3. 없으면 예외 ==

get()        NoSuchElementException: No value present

== 4. null을 감쌀 때 ==
