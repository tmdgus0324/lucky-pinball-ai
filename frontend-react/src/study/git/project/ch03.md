## 커밋 메시지 규칙

처음 커밋 10개는 말머리 없는 영어 문장으로 썼고, 그 뒤로는 말머리를 붙인 한국어로 바꿨습니다. 말머리별 개수입니다(2026-10-14 기준, 전체 68개 중 말머리 없는 커밋은 13개).

| 말머리 | 개수 | 뜻 |
|---|---|---|
| `feat:` | 21 | 기능 추가 |
| `docs:` | 16 | 문서 |
| `fix:` | 9 | 버그 수정 |
| `ci:` | 4 | 자동 테스트·배포 설정 |
| `chore:` | 2 | 잡일(설정 파일 정리 등) |
| `style:`, `refactor:`, `perf:` | 각 1 | 모양, 구조 개선, 성능 |

말머리가 있으면 `git log --oneline`만 봐도 어떤 종류의 변경인지 보입니다. 본문에는 무엇을 바꿨는지 목록으로 적었습니다.

```
feat: 공부하기 > Spring Boot 10~16장 추가

- 10 MyBatis 기초, 11 JPA 기초, 12 트랜잭션, ...
- 예제는 임시 프로젝트에서 실제 빌드·실행한 출력을 실음
```

## 첫 줄과 본문 사이의 빈 줄

10~16장을 커밋할 때 제목과 본문 사이에 빈 줄을 빠뜨린 적이 있습니다. 그러자 `git log --oneline`에 본문 전체가 한 줄로 이어져 나왔습니다. Git은 첫 빈 줄 앞까지를 제목으로 보기 때문입니다.

아직 push하기 전이라 `git commit --amend`로 메시지만 고쳐서 바로잡았습니다. amend는 커밋을 새로 만들어 해시가 바뀌므로, push한 뒤에는 쓰지 않습니다(9장, 12장).

## 골라서 add하기

이 저장소에서는 `git add .` 대신 바꾼 파일을 하나씩 지정해서 담습니다.

```bash
git add devhelp/06_배포_CI_운영환경.md
git add frontend-react/src/study/spring/chapters.ts frontend-react/src/study/spring/notes ...
```

프로젝트 폴더에는 커밋하지 않는 개인 메모와, 확인하려고 잠깐 만든 파일이 섞여 있을 때가 많기 때문입니다. 커밋하기 전에는 `git diff --cached --name-only`로 들어갈 파일 목록을 한 번 더 보고, 개인 메모나 빌드 캐시가 없는지 확인했습니다.
