이 사이트의 코드는 GitHub 저장소 `lucky-pinball-ai` 하나로 관리합니다. 정리에서 본 내용이 실제로 어떻게 나타났는지 봅니다.

## 저장소 만들기

2026-09-22에 프로젝트 폴더(`01_LuckyPinballAI`)에서 `git init`으로 저장소를 만들고 첫 커밋을 했습니다. 그다음 GitHub에 저장소를 만들어 연결하고 push했습니다. 정리 1절처럼 "내 PC 저장소가 먼저, 서버는 나중"인 순서입니다.

```
23e1a37  2026-09-22  Initial commit: AI Lucky Pinball MVP
...
155eec9  2026-10-13  feat: 공부하기 > React 16장 JSP 화면을 React로(게시판) 추가
```

2026-10-14 기준으로 커밋이 68개입니다. 이력이 내 PC에도 전부 있어서, 인터넷이 끊겨도 `git log`로 지난 작업을 모두 볼 수 있습니다.

## commit과 push가 따로라서 생긴 일

Spring Boot 공부하기 10~16장을 만들 때, 2026-10-08에 커밋(`27d9d6b`)만 하고 push는 이틀 뒤인 10-10에 했습니다. 로컬에서 더 확인한 뒤 올리고 싶었기 때문입니다. 그 이틀 동안 GitHub와 배포 사이트에는 10~16장이 없었습니다.

SVN이었다면 commit하는 순간 서버에 올라가서 이렇게 나눌 수 없습니다. Git에서는 "기록은 해 두되, 공개는 나중에"가 됩니다. 반대로 push를 잊으면 동료는 변경을 볼 수 없으니, 운영에서는 "커밋했다"와 "올렸다"를 구분해서 말해야 합니다.

## 브랜치 없이 master 하나

이 저장소는 브랜치가 `master` 하나뿐입니다. 혼자 하는 프로젝트라서 브랜치를 나누고 리뷰받을 일이 없었습니다. 대신 push할 때마다 자동 테스트(CI)가 돌아서, 깨진 코드가 올라가면 바로 알 수 있게 했습니다.

회사 시스템은 여러 사람이 함께 고치기 때문에 브랜치와 Pull Request를 씁니다. 그 흐름은 5~8장에서 봅니다.
