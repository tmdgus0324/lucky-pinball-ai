## .gitignore 세 개

| 위치 | 주요 내용 |
|---|---|
| 맨 위 `.gitignore` | OS·에디터 파일, `node_modules/`, `dist/`, Claude Code 개인 설정(`.claude/settings.local.json`), 개인 메모(`devhelp/00_*.md`) |
| `backend/.gitignore` | `build/`, `.gradle`, `data/`(로컬 H2 DB 파일), IDE 설정 |
| `frontend-react/.gitignore` | 공부하기 예제 폴더에 IDE가 만드는 Gradle 캐시 |

`frontend-react/.gitignore`는 공부하기 Spring Boot 예제를 만들 때 추가했습니다. 에디터의 Java 확장이 예제 폴더 안에 `.gradle/` 캐시를 만들어서 `git status`에 계속 보였기 때문입니다.

## 개인 메모를 규칙으로 빼기

면접 준비나 개선 로드맵 같은 개인 메모는 `devhelp/00_` 로 시작하는 이름으로 만들고, 이 이름 규칙을 `.gitignore`에 넣었습니다.

```gitignore
# devhelp/00_*.md는 커밋하지 않는 개인 작업 메모 규칙 (로드맵, 면접 준비 등)
devhelp/00_*.md
```

파일마다 조심하는 대신 이름 규칙 하나로 빼면, 실수로 `git add`해도 들어가지 않습니다. 이 메모들은 공개 저장소에는 없고, 따로 만든 비공개 저장소에 올려 두었습니다.

## 비밀 키 검사 훅

Claude API 키가 실수로 커밋되지 않게, 커밋할 때마다 키 모양의 문자열을 찾는 훅(`.git/hooks/pre-commit`)을 두었습니다.

```sh
MATCH=$(git diff --cached | grep -nE '(sk-ant-[A-Za-z0-9_-]{20,}|ANTHROPIC_API_KEY...)')
if [ -n "$MATCH" ]; then
  echo "🚫 커밋 중단: Anthropic API 키로 보이는 문자열이 커밋 내용에 포함되어 있습니다."
  exit 1
fi
```

만들면서 겪은 일이 두 가지 있습니다.

- 처음에는 규칙이 너무 느슨해서, 문서에 예시로 적은 `sk-ant-...`(가짜 값)까지 막았습니다. 실제 키처럼 뒤에 글자가 충분히 이어질 때만 막도록 고쳤습니다.
- `.git/hooks`는 Git이 추적하지 않아서, 다른 PC에서 clone하면 이 훅이 따라오지 않습니다. 노트북에서 작업하려면 훅 파일을 따로 복사해야 합니다. 팀 전체에 적용하려면 저장소 서비스의 비밀값 검사 기능이나 공용 훅 도구를 씁니다.

## 실제로 키가 새어 나갈 뻔한 일

API 키가 커밋 대상은 아니지만 프로젝트 폴더 안의 Claude Code 로컬 설정 파일(`.claude/settings.local.json`)에 들어간 적이 있습니다. 정리 4절의 순서대로 키를 먼저 폐기하고 새 키로 바꿨고, 그 파일을 `.gitignore`에 넣었습니다(2026-09-24). 마무리 점검 때 전체 커밋 이력에서 키 모양의 문자열을 찾았고, 0건이었습니다.
