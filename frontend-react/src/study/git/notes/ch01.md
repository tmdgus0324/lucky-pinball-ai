SVN을 써 왔다면 Git의 명령 이름은 익숙해 보이지만, 같은 이름이 다른 뜻인 경우가 있습니다. 가장 큰 차이는 "커밋이 서버에 바로 올라가지 않는다"는 점입니다. 이 장은 그 차이를 먼저 잡고, 저장소를 만들어 첫 커밋을 해 봅니다.

## 1. 중앙 저장소와 분산 저장소

```
SVN(중앙 집중)                         Git(분산)
   서버 저장소(이력 전체)                  원격 저장소(GitHub, GitLab 등)
     ↑ commit   ↓ update                    ↑ push      ↓ pull
   내 PC: 작업 사본(최신 파일만)           내 PC: 저장소 전체(이력 포함) + 작업 폴더
                                              ↑ commit
```

- SVN은 이력이 서버에만 있습니다. 내 PC에는 파일만 있어서, 이력을 보거나 커밋하려면 서버에 연결돼야 합니다.
- Git은 내 PC에 이력 전체가 있습니다(`.git` 폴더). 커밋, 이력 보기, 브랜치 만들기가 모두 내 PC에서 됩니다.
- 그래서 Git에서는 "커밋"과 "서버에 올리기(push)"가 따로입니다. 커밋만 하고 push하지 않으면 다른 사람은 내 변경을 볼 수 없습니다.

## 2. SVN 명령과 Git 명령

| 하는 일 | SVN | Git |
|---|---|---|
| 처음 받아 오기 | `svn checkout URL` | `git clone URL` |
| 최신으로 맞추기 | `svn update` | `git pull` |
| 변경 올리기 | `svn commit` | `git commit` 후 `git push`(두 단계) |
| 새 파일 등록 | `svn add` | `git add`(새 파일뿐 아니라 수정한 파일도 매번 add) |
| 상태 보기 | `svn status` | `git status` |
| 차이 보기 | `svn diff` | `git diff` |
| 이력 보기 | `svn log` | `git log` |
| 변경 취소 | `svn revert` | `git restore`(9장) |
| 브랜치 만들기 | `svn copy trunk branches/x` | `git branch x`(5장) |
| 브랜치 옮기기 | `svn switch` | `git switch` |
| 줄별 작성자 | `svn blame` | `git blame`(10장) |

헷갈리기 쉬운 것 두 가지입니다.

- `git commit`은 `svn commit`과 달리 서버에 올리지 않습니다. `svn commit`에 해당하는 것은 `git commit` + `git push`입니다.
- `git add`는 새 파일 등록만이 아니라 "이번 커밋에 담을 변경 고르기"입니다. 이미 있는 파일을 고쳐도 다시 add해야 커밋에 들어갑니다(3장).

## 3. 리비전 번호 대신 해시

SVN은 커밋할 때마다 서버가 번호를 하나씩 올려 줍니다(r100, r101). Git은 서버 없이도 커밋해야 해서 번호를 매길 곳이 없습니다. 대신 커밋 내용으로 만든 40자리 해시를 이름으로 씁니다.

```
commit f404f339762d45f72a0a2e652ecbadc66daa22a8
```

평소에는 앞 7자리(`f404f33`)만 써도 됩니다. 해시는 순서를 뜻하지 않으므로 "몇 번이 더 최신인가"는 `git log`로 봅니다. 가장 최근 커밋은 `HEAD`라는 이름으로도 부를 수 있습니다.

## 4. 그 밖의 차이

| 구분 | SVN | Git |
|---|---|---|
| 일부 폴더만 받기 | 하위 폴더만 checkout 가능 | 기본은 저장소 전체를 clone |
| 빈 폴더 | 추적함 | 추적하지 않음(빈 폴더를 남기려면 `.gitkeep` 같은 빈 파일을 둔다) |
| 파일 잠금 | `svn lock` 기능 | 기본 기능에는 없음 |
| 브랜치 비용 | 폴더 전체를 복사 | 이름표 하나라 거의 비용이 없음 |

## 5. 처음 해 보기

```bash
git init reservation            # 저장소 만들기(.git 폴더가 생긴다)
cd reservation
echo "객실 예약 시스템" > README.md
git add README.md
git commit -m "README 추가"
git log --oneline
```

실행 결과에서 `git remote -v`가 아무것도 출력하지 않는 것을 볼 수 있습니다. 연결된 서버가 아직 없는데도 커밋과 이력 보기가 모두 된다는 뜻입니다.

## 확인 문제

1. SVN의 `svn commit`에 해당하는 Git 명령은 무엇인가요?
2. `git commit`까지만 하고 퇴근했습니다. 동료가 내 변경을 볼 수 있나요?
3. Git이 SVN처럼 r100, r101 같은 번호를 쓰지 않는 이유는?
4. 이미 커밋한 파일을 고쳤습니다. `git commit`만 하면 이 수정이 들어가나요?
5. 서버에 연결되지 않은 상태에서 Git으로 할 수 있는 것과 없는 것은?

## 정답

1. `git commit` 후 `git push`입니다. Git의 commit은 내 PC 저장소에만 기록합니다.
2. 볼 수 없습니다. push해야 원격 저장소에 올라갑니다.
3. 커밋을 서버 없이 각자 PC에서 하므로, 번호를 하나씩 올려 줄 중앙 서버가 없기 때문입니다. 대신 내용으로 만든 해시를 씁니다.
4. 들어가지 않습니다. `git add`로 다시 담거나 `git commit -a`를 써야 합니다.
5. 커밋, 이력 보기, 차이 보기, 브랜치 만들기는 됩니다. 원격 저장소와 주고받는 clone, pull, push는 안 됩니다.
