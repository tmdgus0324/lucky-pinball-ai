Git에는 SVN에 없는 "스테이징 영역"이 있습니다. 처음에는 단계가 하나 더 있는 것 같아 번거롭지만, 바꾼 것 중 일부만 골라 커밋할 수 있게 해 줍니다. 이 장은 파일이 작업 폴더에서 저장소까지 가는 세 단계를 봅니다.

## 1. 세 단계

```
작업 폴더  ──git add──>  스테이징 영역  ──git commit──>  저장소(.git)
(지금 고치는 파일)        (이번 커밋에 담을 것)            (기록된 이력)
```

- 작업 폴더: 에디터로 고치는 실제 파일
- 스테이징 영역: "이번 커밋에 넣을 변경"을 모아 두는 곳(index라고도 부른다)
- 저장소: 커밋으로 기록된 이력

SVN은 `svn commit` 하나로 바뀐 파일을 올리지만, Git은 add로 담고 commit으로 기록합니다. 그래서 여러 파일을 고쳤어도 관련 있는 것만 골라 커밋을 나눌 수 있습니다(실행 결과의 `Reservation.java`만 커밋한 부분).

## 2. git status 읽기

| 영역 | 상태 | 뜻 |
|---|---|---|
| Untracked files | 추적 안 함 | 저장소에 한 번도 들어간 적 없는 새 파일 |
| Changes not staged for commit | 수정됨 | 고쳤지만 아직 add하지 않음 |
| Changes to be committed | 스테이징됨 | add해서 다음 커밋에 들어갈 변경 |

`git status -s`(짧게 보기)는 앞 글자가 스테이징, 뒤 글자가 작업 폴더 상태입니다.

```
 M Room.java          수정했지만 add 안 함
M  Room.java          add함
MM Room.java          add한 뒤에 또 고침
A  Reservation.java   새로 add함
?? Memo.txt           추적 안 함
```

## 3. 차이 보기

| 명령 | 비교 대상 |
|---|---|
| `git diff` | 작업 폴더 ↔ 스테이징(아직 add하지 않은 변경) |
| `git diff --staged` | 스테이징 ↔ 마지막 커밋(커밋하면 들어갈 변경) |
| `git diff HEAD` | 작업 폴더 ↔ 마지막 커밋(둘 다) |

커밋하기 전에 `git diff --staged`로 무엇이 들어가는지 한 번 보는 습관을 들이면, 디버그용 코드나 비밀번호가 섞여 들어가는 사고를 줄일 수 있습니다.

## 4. 커밋 메시지

```
fix: 객실 예약 시 체크아웃 날짜 검증 누락 수정

- 체크아웃이 체크인보다 빠르면 400을 돌려준다
- 관련 문의: #1234
```

- 첫 줄은 무엇을 했는지 짧게(50자 안팎) 씁니다. `git log --oneline`에 이 줄만 보입니다.
- 한 줄 띄우고 본문에 이유와 자세한 내용을 씁니다.
- 회사마다 규칙(말머리, 이슈 번호 등)이 있으면 그것을 따릅니다.
- 한 커밋에는 한 가지 일만 담습니다. 기능 추가와 버그 수정을 섞으면 나중에 하나만 되돌리기 어렵습니다(9장).

## 5. 자주 쓰는 모양

```bash
git add 파일1 파일2        # 골라서 담기
git add .                  # 현재 폴더 아래 전부 담기(무엇이 들어가는지 status로 먼저 확인)
git commit -m "메시지"
git commit -am "메시지"    # 추적 중인 파일의 수정을 모두 담아 커밋(새 파일은 안 들어감)
git log --oneline          # 한 줄씩 이력
git log --stat             # 커밋마다 바뀐 파일
git show HEAD~1            # 하나 전 커밋의 내용
```

`HEAD`는 지금 위치(보통 마지막 커밋), `HEAD~1`은 그 하나 전, `HEAD~2`는 두 개 전입니다.

## 확인 문제

1. SVN에는 없고 Git에만 있는 단계는 무엇이고, 무엇이 좋은가요?
2. `git status -s`에 ` M Room.java`와 `M  Room.java`는 무엇이 다른가요?
3. add한 뒤에 같은 파일을 또 고쳤습니다. 이 상태에서 커밋하면 나중에 고친 부분도 들어가나요?
4. 커밋하기 직전에, 커밋에 들어갈 변경만 보려면 어떤 명령을 쓰나요?
5. `git commit -am`으로 새로 만든 파일도 커밋되나요?

## 정답

1. 스테이징 영역입니다. 바꾼 것 중 일부만 골라 커밋을 나눌 수 있습니다.
2. 앞 칸이 스테이징, 뒤 칸이 작업 폴더입니다. ` M`은 수정했지만 add 안 함, `M `은 add해서 스테이징된 상태입니다.
3. 들어가지 않습니다. 커밋에는 add한 시점의 내용만 들어가고, 나중 수정은 다시 add해야 합니다(`MM` 상태).
4. `git diff --staged`입니다.
5. 안 됩니다. `-a`는 이미 추적 중인 파일만 담습니다. 새 파일은 `git add`로 먼저 담아야 합니다.
