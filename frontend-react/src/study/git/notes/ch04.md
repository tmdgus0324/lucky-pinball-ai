저장소에는 소스와 함께 공유할 설정만 넣습니다. 빌드 결과물, 로그, 내 PC 전용 설정, 비밀번호와 API 키는 넣지 않습니다. 특히 비밀값은 한 번 커밋하면 파일을 지워도 이력에 남기 때문에, 넣기 전에 막는 것이 가장 중요합니다.

## 1. 넣지 말아야 할 것

| 종류 | 예 | 이유 |
|---|---|---|
| 빌드 결과물 | `build/`, `target/`, `dist/`, `*.jar` | 소스로 언제든 다시 만들 수 있고, 용량이 크다 |
| 의존성 폴더 | `node_modules/`, `.gradle/` | 설치 명령으로 받는다 |
| 로그, 임시 파일 | `logs/`, `*.log`, `*.tmp` | 실행할 때마다 바뀐다 |
| IDE·OS 파일 | `.idea/`, `.vscode/`, `.classpath`, `Thumbs.db` | 사람마다 다르다 |
| 내 PC 전용 설정 | `application-local.yml`, `.env` | 사람마다 다르고 비밀값이 섞이기 쉽다 |
| 비밀값 | DB 비밀번호, API 키, 인증서 | 저장소를 볼 수 있는 모든 사람에게 노출된다 |

## 2. .gitignore 문법

```gitignore
# build 폴더 전체(어느 위치에 있든)
build/
# 확장자가 log인 파일
*.log
# 맨 앞의 / : 저장소 맨 위의 그 파일만
/config.local.yml
# ! : 위 규칙에서 다시 빼기(이 파일은 추적)
!important.log
# 어느 깊이에 있든 temp
**/temp
```

- 주석은 줄 맨 앞의 `#`만 인정됩니다. 규칙 뒤에 `# 설명`을 붙이면 그것까지 규칙으로 읽혀서 동작하지 않습니다.
- 폴더마다 `.gitignore`를 둘 수 있고, 그 폴더 아래에만 적용됩니다.
- 어떤 규칙 때문에 빠졌는지는 `git check-ignore -v 파일`로 봅니다(실행 결과 참고).
- OS나 IDE 파일처럼 모든 저장소에서 빼고 싶은 것은 개인 전역 설정(`core.excludesFile`)에 두는 방법도 있습니다.

## 3. 이미 추적 중인 파일은 .gitignore로 안 빠진다

`.gitignore`는 아직 추적하지 않는 파일에만 적용됩니다. 실행 결과에서 `application.properties`를 커밋한 뒤 `.gitignore`에 넣었지만, 고치자 `M`(수정됨)으로 계속 나왔습니다.

```bash
git rm --cached application.properties   # 추적만 멈춘다. 내 PC의 파일은 남는다
git commit -m "application.properties 추적 중단"
```

`--cached` 없이 `git rm`을 하면 내 PC의 파일까지 지워집니다. 그리고 추적을 멈춰도, 그 파일이 들어 있던 예전 커밋에는 계속 남아 있습니다.

## 4. 비밀값을 커밋했다면

실행 결과 마지막 부분처럼, 파일을 지우는 커밋을 해도 `git show HEAD~1:payment.properties`로 예전 내용이 그대로 보입니다. 저장소를 clone한 사람은 누구나 이력을 갖고 있습니다.

대응 순서입니다.

1. 키와 비밀번호부터 바꾸거나 폐기합니다. 이미 누군가 받아 갔을 수 있어서, 이력을 지우는 것보다 이것이 먼저입니다.
2. 이력에서 지울지는 팀과 정합니다. `git filter-repo` 같은 도구로 이력을 다시 쓰면 커밋 해시가 모두 바뀌어서, 강제 push와 팀 전체의 다시 clone이 필요합니다.
3. 다시 생기지 않게 막습니다. 비밀값은 환경변수나 서버 설정으로 넣고, 커밋 전에 검사하는 훅이나 저장소 서비스의 비밀값 검사 기능을 켭니다.

push하지 않은 마지막 커밋이라면 `git commit --amend`나 `git reset`으로 커밋 자체를 고칠 수 있습니다(9장). 그래도 키가 내 PC 밖으로 나간 적이 없는지 확인하고, 애매하면 바꿉니다.

## 5. 빈 폴더와 .gitkeep

Git은 빈 폴더를 추적하지 않습니다. `logs/`처럼 폴더는 있어야 하고 내용은 넣지 않을 때는, 빈 파일(`.gitkeep`)을 하나 넣고 `.gitignore`에서 그 파일만 빼 줍니다.

```gitignore
logs/*
!logs/.gitkeep
```

## 정답

1. 빌드 결과물, 로그, 내 PC 전용 설정, 비밀값(비밀번호, API 키), IDE 설정 등입니다.
2. `git rm --cached application.properties`로 추적을 멈추고 커밋합니다.
3. `git rm`은 저장소와 내 PC에서 모두 지우고, `--cached`는 저장소 추적만 멈추고 파일은 남깁니다.
4. 그 키를 폐기하거나 바꾸는 것입니다. 이미 누군가 받아 갔을 수 있습니다.
5. 이력을 다시 쓰면 커밋 해시가 모두 바뀌어서, 강제 push와 팀 전체의 다시 clone이 필요하기 때문입니다.
