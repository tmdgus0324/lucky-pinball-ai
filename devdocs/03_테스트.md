# 03. 테스트

백엔드 JUnit 테스트 109개가 GitHub Actions에서 push할 때마다 실행됩니다. 프론트엔드는 CI에서 `lint`와 `build`(타입 검사 포함)만 확인합니다.

## 1. 실행

```bash
cd backend
./gradlew cleanTest test
env -u ANTHROPIC_API_KEY -u ANTHROPIC_AUTH_TOKEN ./gradlew cleanTest test   # CI와 같은 조건(키 없음)
```

내 PC에 `ANTHROPIC_API_KEY`가 있으면 "키 없음" 테스트 2개가 건너뛰어집니다. 이것 때문에 CI에서만 실패한 적이 있어서, 키를 뺀 조건으로도 한 번 더 돌립니다. `cleanTest`는 코드가 그대로여도 테스트를 다시 실행하게 합니다.

## 2. 원칙

- 진짜 Claude API는 비용이 들어서 테스트에서 부르지 않습니다. 대신 가짜를 씁니다.
  - 가짜 `FortuneService`: 성공·실패를 마음대로 정해서 캐시·임시 점수·동시 요청을 확인
  - 가짜 Claude 서버(JDK `HttpServer`): 타임아웃, 429, 500, 끊긴 연결 같은 실제 네트워크 실패를 재현
  - `MockFortuneGenerator`: 항상 같은 점수를 내는 규칙 기반 생성기
- 테스트는 매번 새로 만드는 메모리 H2를 써서 개발 DB를 건드리지 않습니다.
- 버그는 재현 테스트를 먼저 만들어 실패하는 것을 확인한 뒤 고칩니다.

## 3. 무엇을 확인하나

| 종류 | 대표 테스트 | 확인하는 것 |
|---|---|---|
| HTTP 통합 | `ApiFlowIntegrationTest` | 실제로 서버를 띄워 게임 한 판 전체, 오류 응답, 관리자 인증 |
| 운세·DB | `FortuneQueryServiceTest`, `PlayerListQueryCountTest` | 캐시 재사용, 임시 점수, 같은 사람 동시 요청 시 AI 1번, 참가자 목록 쿼리 수(N+1 방지) |
| Claude 실패 | `ClaudeFortuneGeneratorTest`, `AiHealthServiceTest` | 타임아웃·재시도 횟수, 실패 종류 구분(키 없음, 크레딧 부족 등) |
| 게임 규칙 | `GameServiceTest`, `BuffCalculatorTest` | 인원 제한, 출발 높이 계산, 게임 상태 순서, 결과 검증 |
| 필터·관리자 | `RateLimitFilterTest`, `AdminAuthFilterTest` 등 | 요청 제한과 우회 차단, 추적 ID, 토큰 검증, 예외별 상태 코드 |

## 4. 프론트엔드

자동 테스트는 없습니다. 기능을 바꿀 때마다 Playwright 스크립트로 브라우저를 직접 조작해서 확인했습니다(API 응답을 가짜로 바꿔 끼우는 방식 포함). 이 스크립트는 저장소에 넣지 않았습니다.
