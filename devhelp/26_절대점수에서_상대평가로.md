# 26. 버프를 절대점수 대신 참가자 간 상대평가로

## 1. 문제 — AI 점수가 좁게 몰려서 선형 공식도 무의미해짐

devhelp/24에서 `BuffCalculator`를 20점 단위 계단식에서 선형(`startY=(100-score)*2`)으로 바꿨지만, 새로 만든 "AI TEST" 버튼(devhelp/25.5)으로 4명을 한꺼번에 등록해서 실제로 테스트해보니 Claude가 매긴 점수가 72/76/74/74점처럼 4점 범위 안에 몰렸다. devhelp/14에서 이미 예견됐던 "점수가 60~70점대로 쏠리는 경향"이 실제로 재현된 것 — 공식 자체는 선형이라도, 입력값(AI 점수)의 실제 분포가 좁으면 결과(시작 높이 차이)도 8px 정도로 사실상 안 보이는 수준이 된다.

## 2. 해법 — 절대 0~100점이 아니라 "이번 판 참가자 중 최고점자 대비 상대 순위"

사용자 제안: 점수를 절대값으로 안 쓰고, 같이 등록된 사람들끼리 비교해서 `최고점자 - 내 점수`만큼 공 개수 단위로 뒤에서 출발시킨다. 상대 차이가 너무 크게 벌어지는 걸 막기 위해 10점(=공 10개)에서 잘라낸다.

- `BuffCalculator.relativeStartY(myScore, maxScoreInGame)`: `gap = min(10, max(0, maxScore - myScore))`, `startY = gap * 26`(공 지름 px). 기존 `fromScore()`(절대점수→tier)는 카드 배지 색상용으로 그대로 남겨뒀다 — 이번 변경은 `startY`에만 적용된다.
- 계산 위치는 `GameService.createGame()` — 개별 조회 엔드포인트(`POST /api/fortune`)는 참가자 한 명씩 독립 호출이라 "이번 판에 누가 같이 뛰는지"를 모른다. `createGame()`은 이미 `playerIds` 전체를 한 번에 받아서 각자의 원점수를 조회하므로, 여기서 최고점을 구해 그룹 전체의 `startY`를 다시 계산해 끼워 넣는 두 번째 패스(`applyRelativeStartY`)를 추가했다.
- 생년월일 미입력(NONE, 점수 자체가 없음) 참가자는 비교 대상에서 빠지고 기존 `Buff(0,0)` 그대로 — 애초에 운세를 안 받았으니 상대 비교 자체가 성립하지 않는다.
- "빠른 추가" 참가자는 원래 서버에 점수를 안 보내는 구조(devhelp/25)라 이 로직과 완전히 무관 — 프론트(`GamePage.handleStartGame`)가 게임 생성 응답을 받은 뒤 이미 자체 숨김 점수로 `buff.startY`를 덮어쓰고 있고, 이번 변경 후에도 그 덮어쓰기가 마지막에 적용되므로 서로 간섭하지 않는다.

## 3. 안전 마진 재조정 — devhelp/25 재발 방지

상대평가의 최대 시작 높이가 200(구 절대값 최대)에서 **260**(10×26)으로 커지면서, `spawnY = 20 + startY`의 최댓값도 220→**280**이 됐다. 그런데 `pegField.startY`(첫 못 행 y좌표)가 정확히 280이라 여유가 0이 되어 devhelp/25에서 어렵게 고친 "공이 못 행과 겹쳐서 끼는" 문제가 재발할 뻔했다 — `pegField.startY`를 **340**으로 올려 60px 여유를 되찾았다(`zoomStartY` 리터럴도 같이 `340+5*50=590`으로 조정). `frontend-react/src/game/engine.ts`와 레거시 `frontend/js/game.js` 양쪽 다 반영 — 둘 다 같은 백엔드 응답을 그대로 쓰기 때문에 하나만 고치면 나머지가 다시 끼임 위험에 노출된다.

## 4. 2번 섹션(오늘의 운세) 미리보기도 같은 값을 보여줘야 함

`POST /api/fortune`은 참가자 한 명씩 독립 호출이라 상대평가를 모른 채 예전 절대값 `buff.startY`를 그대로 반환한다. 그대로 두면 2번 섹션 카드가 보여주는 숫자와 실제 게임에서 벌어지는 높이 차이가 서로 다른 값이 되어버린다(사용자에게 확인해서 "게임과 동일한 값을 미리 보여준다"로 확정) — 그래서 프론트에서 배치로 받은 점수들 중 최댓값을 구해 **같은 공식을 다시 계산**해서 화면에 보여준다.

- `frontend-react/src/utils/relativeBuff.ts`(신규) — `RELATIVE_GAP_CAP=10`, `BALL_DIAMETER_PX=26` 상수와 `computeRelativeStartY()`를 백엔드 `BuffCalculator`와 동일하게 복제(주석으로 동기화 필요성 명시 — `quickAddBuff.ts`가 이미 같은 패턴으로 다른 상수를 복제해둔 선례가 있음).
- `FortuneSection.tsx`(React), `main.js`의 `renderFortuneGrid()`(레거시) 둘 다 이 계산을 반영 — 두 프론트가 같은 백엔드 응답 포맷을 공유하므로 하나만 고치면 나머지 화면이 여전히 무의미한 절대값을 보여주게 된다.

## 5. 검증

AI TEST 버튼으로 4명 등록 → 실제 Claude 점수 62/76/72/68 → 2번 섹션 카드에 표시된 시작 높이가 **+260/+0/+104/+208**로, 계산식(`(76-내점수, 캡10)×26`)과 정확히 일치하는 것 확인. 게임 시작 후 실제 공 스폰 순서(개발자도구로 각 공의 `top` 값 측정)도 이 순서와 정확히 일치했다.

devhelp/25 방식(nudge 발동 횟수 계측)으로 재발 여부도 확인 — AI TEST 4명 + 빠른 추가 4명을 섞은 8명 풀 게임에서 **nudge 0회, 11초 만에 정상 완주**. 안전 마진 조정이 제대로 됐고, 혼합 게임(실제 AI 점수 참가자 + 숨김 랜덤 점수 참가자)도 서로 간섭 없이 정상 동작함을 확인했다.
