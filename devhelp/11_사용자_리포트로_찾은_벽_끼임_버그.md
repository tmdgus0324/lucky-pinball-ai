# 11. 사용자 리포트로 찾은 "벽에 걸림" 버그

`09_헤드리스_물리_테스트로_버그_발견.md`에서 한 번 안전장치(정체 감지 후 흔들기)로 막아뒀던 문제가, 실제로는 완전히 해결된 게 아니라 **증상만 가려져 있었다**는 걸 사용자가 직접 실행해보고 알려준 덕분에 알게 된 과정입니다.

## 1. 사용자가 관찰한 현상

참가자 4명(1, 2, 3, 4)으로 게임을 돌렸을 때, 참가자 "1"이 당첨(가장 늦게 도착)됐는데 — 정상적으로 굴러 내려온 게 아니라 **"제일 왼쪽 끝에 걸려서 내려오는 식"**으로 움직였다는 리포트를 받았습니다. "걸리면 못 내려올 것 같은데 정상 동작이 맞냐"는 날카로운 질문이었습니다.

## 2. 정답: 아니요, 정상이 아니었습니다

`09` 문서에서 넣었던 안전장치를 다시 보면:

```js
if (adapter.getSpeed(state.body) < 0.05) {
  state.stallTicks++;
  if (state.stallTicks > 45) {
    adapter.nudge(state.body); // 살짝 흔들어서 강제로 이동시킴
    state.stallTicks = 0;
  }
}
```

이 로직은 "공이 완전히 멈추는 것"은 막아줬지만, **왜 자꾸 멈추는지(근본 원인)는 고치지 못한 상태**였습니다. 그 결과 화면에서는 "0.75초 정도 멈칫 → 강제로 튕겨나감 → 조금 가다 다시 멈칫 → 또 튕겨나감"이 반복되는, 사용자가 본 것과 정확히 일치하는 "걸렸다 풀렸다"하는 부자연스러운 움직임으로 나타났습니다. 게임 자체는 끝나지만(당첨자 결과는 유효), 물리적으로 매끄럽지 않았던 것 — **사용자의 관찰이 맞았습니다.**

## 3. 진짜 원인

`04_pinball-map-design.md`의 벽은 위(폭 전체)에서 아래(중앙으로 좁아짐)로 이어지는 깔때기 모양입니다. 그런데 못 배열을 만들 때 벽에서 못까지의 여백을 38px로만 뒀는데, **이 여백이 매 행(row)마다 거의 똑같아서, 벽을 따라 못들이 일렬로 늘어선 "레일"처럼 배치**돼 있었습니다. 공이 벽 쪽으로 붙어서 떨어지면, 벽과 그 옆 못 사이의 좁은 틈에 물리적으로 끼이기 쉬운 구조였던 것입니다 — 안전장치가 그걸 한 번씩 풀어줘도, 조금 내려가면 바로 다음 행의 못에서 또 같은 일이 반복됐습니다.

## 4. 수정

두 가지를 함께 고쳤습니다 (`frontend/js/game.js`).

1. **벽 근처에는 못을 아예 두지 않는 여유 구간을 크게 넓힘** (38px → 70px, `PEG_WALL_CLEARANCE` 상수로 명명). 이제 벽을 따라 내려가는 공이 못과 동시에 맞닿을 일이 훨씬 줄어듭니다.
2. **모든 물리 바디(공/못/벽)의 마찰력을 0으로 설정**. 마찰이 있으면 공이 벽/못 표면에 "달라붙듯" 저항을 받을 수 있는데, 마찰을 없애면 부딪히고 튕겨 나가기만 할 뿐 표면에 붙잡히지 않습니다.

기존의 "정체 감지 후 흔들기" 안전장치는 **그대로 남겨뒀습니다** — 이제는 실제로 거의 발동하지 않는, 정말 예외적인 경우를 위한 최후의 보험 역할입니다.

## 5. 수정 후 재검증

`09`에서 썼던 것과 같은 헤드리스 테스트 방식으로, 안전장치가 몇 번 발동하는지(nudge count)를 세어봤습니다.

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 8명 게임, 8회 반복 시 평균 완료 시간 | 약 9~27초 (안전장치가 자주 개입) | 약 2.8~3.0초 |
| 안전장치(nudge) 발동 횟수 | 게임당 여러 번 | **8회 전부 0번** |

완료 시간도 훨씬 짧고 일정해졌다는 것 자체가, 공이 더 이상 걸리지 않고 매끄럽게 굴러 내려온다는 걸 뒷받침합니다. 추가로 Playwright로 실제 브라우저에서 벽 근처 공(참가자 "1")의 움직임을 여러 프레임 연속으로 캡처해 확인했고, 벽과 못 사이에 눈에 띄는 여백이 생겨 더 이상 걸리는 모습 없이 자연스럽게 내려오는 것을 눈으로도 확인했습니다.

## 6. 배운 점

- 안전장치(재시도/복구 로직)는 "증상을 완화"할 수는 있지만, **근본 원인을 찾아 고치지 않으면 그 증상 자체가 버그로 남습니다.** `09`에서 "게임이 멈추지 않는다"는 것만 확인하고 넘어갔던 게 이번 리포트의 원인이었습니다 — 헤드리스 테스트가 "완료 여부"는 검증했지만 "움직임이 자연스러운가"까지는 검증하지 못했기 때문입니다.
- 이번에도 검증 지표를 하나 추가한 게 원인 확인에 결정적이었습니다 — "안전장치가 몇 번 발동했는가"라는 숫자 하나가 수정 전/후 차이를 명확하게 보여줬습니다.
- 사용자가 실제로 써보고 남긴 "이상한데?"라는 관찰이, 자동화된 테스트로는 못 잡아낸 문제를 잡아낸 사례입니다 — 자동 테스트와 실사용자 피드백은 서로 다른 종류의 버그를 잡아낸다는 걸 보여줍니다.
