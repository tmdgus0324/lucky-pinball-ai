# 14. 생년월일 입력 방식 개선과 운세 다양성 확보

실제로 여러 명을 등록해서 써보신 사용자 피드백 2가지를 반영했습니다.

## 1. 생년월일 6자리 자동 변환

기존에는 브라우저 기본 `<input type="date">`를 썼는데, 화면에 "198902-02-13"처럼 어색하게 입력되는 문제가 있었습니다. 요청하신 대로 **6자리 숫자(YYMMDD) 입력**으로 바꿨습니다.

```js
function parseBirthDateShorthand(raw) {
  const digits = raw.replace(/\D/g, '');
  if (digits.length !== 6) return null;

  const yy = parseInt(digits.slice(0, 2), 10);
  const month = parseInt(digits.slice(2, 4), 10);
  const day = parseInt(digits.slice(4, 6), 10);
  if (month < 1 || month > 12 || day < 1 || day > 31) return null;

  const year = (yy >= 50 ? 1900 : 2000) + yy;
  return `${year}-${String(month).padStart(2, '0')}-${String(day).padStart(2, '0')}`;
}
```

말씀하신 규칙(YY가 50 이상이면 1900년대, 미만이면 2000년대 — 주민등록번호 앞자리와 같은 관례) 그대로 구현했습니다. `880324` → `1988-03-24`, `130101` → `2013-01-01`로 정확히 변환되는 것을 확인했습니다. 형식이 안 맞으면(6자리가 아니거나 월/일이 범위를 벗어나면) 등록 자체를 막고 안내 메시지를 보여줍니다.

입력 필드는 `<input type="date">`에서 `<input type="text" inputmode="numeric">`로 바꿔서, 모바일에서는 숫자 키패드가 뜨면서도 자유롭게 6자리 숫자를 타이핑할 수 있게 했습니다.

## 2. 운세 내용이 다 비슷해 보이는 문제

스크린샷을 보니 실제로 심각했습니다 — 4명 중 3명이 **"오늘은 새로운 기회가 찾아오는 날입니다. 긍정적인 마음으로 도전하면 좋은 결과를 얻을 수 있습니다."** 를 토씨만 다르게 그대로 받았더군요. 원인과 해결 과정을 기록합니다.

### 원인: Claude에게 "차별화할 재료"가 없었다

기존 프롬프트는 `이름 + 생년월일`만 던져주고 "운세를 봐줘"라고 했는데, 이 정도 정보로는 Claude 입장에서 "이 사람만의 특징"을 잡을 실마리가 부족해서, 무난하고 안전한 일반적인 문구로 수렴하는 경향이 있었습니다. 게다가 API 호출은 매번 완전히 독립적(서로 다른 대화)이라, "방금 다른 사람에게 이미 비슷한 말을 했으니 이번엔 다르게 써야지" 같은 판단 자체를 할 수가 없는 구조입니다.

### 해결 1: 사람마다 다른 "재료"를 직접 계산해서 프롬프트에 넣기

생년월일로부터 서버(Java)에서 미리 계산할 수 있는 정보를 뽑아서 프롬프트에 함께 넣었습니다.

- **띠**: `(년도 % 12)`로 12간지 계산
- **태어난 계절**: 월(月)로 봄/여름/가을/겨울 판단
- **오늘/생일의 요일**: `LocalDate.getDayOfWeek().getDisplayName(TextStyle.FULL, Locale.KOREAN)` — 자바 표준 라이브러리가 한국어 요일명을 바로 줘서 직접 매핑 코드를 짤 필요가 없었습니다.
- **생년월일 숫자의 합**(예: 1997-07-15 → 1+9+9+7+0+7+1+5 = 39): 사람마다 기계적으로 다른 값이 나오는 "계산 재료"를 명시적으로 던져주고, "이 숫자를 바탕으로 점수를 계산하듯 정해달라"고 요청했습니다.

그리고 스키마 설명(`@JsonPropertyDescription`)과 프롬프트 양쪽에 "뻔한 문구 금지, 띠/계절/요일을 활용해서 그 사람만을 위한 것처럼 구체적으로" 라는 지시를 명시했습니다.

### 결과: 메시지는 확실히 좋아졌고, 점수는 여전히 한계가 있음

같은 날 5명을 연달아 조회해서 실제로 비교한 결과입니다.

| 이름 | 생년월일 | 점수 | 행운숫자 | 메시지(요약) |
|---|---|---|---|---|
| 박서준 | 1993-05-11 | 73 | 56 | 닭띠·봄·화요일 언급, 새 아이디어 |
| 최유리 | 1985-12-29 | 62 | 73 | 소띠·겨울 언급, 새 인연 |
| 정민재 | 2005-07-02 | 72 | 61 | 닭띠·여름 언급, 소통에서 좋은 결과 |
| 강나영 | 1978-04-16 | 74 | 72 | 말띠·봄 언급, 도전 기질 |
| 오태양 | 2010-09-08 | 73 | 47 | 호랑이 기백, 가을 언급 |

- **메시지**: 개선 전엔 거의 동일했던 문장이, 이제는 사람마다 확실히 다른 내용(띠/계절/요일이 자연스럽게 녹아든 문장)으로 나옵니다 — 원래 요청하신 부분은 확실히 해결됐습니다.
- **행운의 숫자**: 개선 전엔 4명 전원이 `47`로 완전히 동일했는데, 개선 후엔 56/73/61/72/47로 다양해졌습니다.
- **점수**: 62~74점 사이로 여전히 좁게 몰려있습니다. "0~100 전 구간을 활용해달라", "생년월일 숫자 합을 계산 재료로 써달라"고 명시적으로 요청했는데도, Haiku 4.5가 "무난하게 긍정적인 점수"로 수렴하는 경향 자체는 완전히 없애지 못했습니다 — **프롬프트만으로 개선할 수 있는 한계**에 도달한 것으로 보입니다.

### 참고: 점수까지 더 다양하게 만들고 싶다면

프롬프트 개선만으로는 한계가 있으니, 다음 단계로는 서버에서 계산한 "생년월일 숫자 합" 같은 값을 점수 계산에 일부 직접 반영하는 방식(AI 점수와 결정론적 계산값을 섞는 하이브리드)을 고려할 수 있습니다. 다만 이건 "점수가 AI의 순수 판단"이라는 지금 컨셉을 살짝 바꾸는 설계 결정이라, 필요하시면 별도로 논의해서 진행하는 게 좋을 것 같습니다 — 이번에는 사용자가 지적하신 "메시지 내용의 다양성" 문제 해결에 집중했습니다.
