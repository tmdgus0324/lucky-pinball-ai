# 37. 결과 배너를 맵 위로, 버튼을 제목 줄로, 빠른 추가 이름을 "N번"으로

직접 테스트해보다가 나온 화면 개선 3건이다. 전부 React 프론트(`frontend-react`)만 바꿨다 — 화면 구성 변경이라 물리 엔진을 공유하는 레거시 `frontend/`에는 반영하지 않았다(devhelp/25의 "UI 전용 기능은 React만" 기준과 같다).

## 1. 당첨 결과를 맵 위 오버레이로

**문제**: 게임이 끝나면 아래에 "4. 결과" 패널이 새로 생겨서, 결과를 보려면 스크롤을 해야 했다.

**해결**: "4. 결과" 패널을 없애고, 같은 배너(🔔 + "N번 님 당첨!")를 **맵 위에 겹쳐서** 띄운다. 맵 위 ✕로 닫을 수 있다(겹쳐 있는 채로 계속 못 치우면 맵을 가리니까).

**위치를 정한 근거**
- 카메라는 선두 공을 **보드 요소의 세로 중앙(50%)** 에 고정해서 따라간다(`applyCamera`). 그래서 게임 끝 무렵에 사용자의 시선과 결승선은 보드 중앙 높이에 있다. 배너를 그 근처에 두면 스크롤이 필요 없다.
- 배너의 **아래쪽 가장자리**를 46%에 맞췄다(`top: 46%; transform: translateY(-100%)`). 처음엔 위쪽 가장자리를 36%에 맞췄는데, 보드가 축소되는 모바일(폭 300px → 높이 약 810px)에서는 배너가 상대적으로 커서 결승선을 가렸다. 아래쪽 기준으로 바꾸니 데스크톱·모바일 둘 다 결승선과 공이 보인다.
- `position: sticky`는 쓰지 않았다. 상위 `.main-content`에 `overflow-x: auto`가 있으면 그 요소가 스크롤 컨테이너가 돼서(세로도 `auto`로 계산됨) 페이지 스크롤에 sticky가 안 걸린다. 이 속성은 관리자 표의 가로 스크롤 때문에 있는 것으로 보여 건드리지 않았다.

**구조**: 배너를 보드(`.pinball-board`) 안에 넣으면 엔진이 `boardEl.innerHTML = ''`로 비울 때 같이 지워진다. 그래서 보드 옆 **형제 요소**(`.board-wrap` 안)로 두고, `PinballBoard`에 `overlay` prop을 추가해 `GamePage`가 결과 배너를 넘기게 했다. `#resultSection` id는 배너에 그대로 남겼다(테스트 스크립트가 이 id로 게임 종료를 판단). 배너의 게임 ID(UUID) 줄은 오버레이에서 뺐다 — 맵 위에서는 시각적 잡음이고, 관리자 화면에 남아있다.

## 2. 빠른 추가 이름: "게스트N" → "N번"

- 이름은 `1번, 2번, ...` 형식. 번호는 **현재 참가자 목록에 없는 가장 작은 번호**부터 채운다. 전체 초기화 후에는 항상 1번부터 나가고, 이미 1·2·3번이 있으면 4번부터 이어진다.
- "매번 무조건 1번부터"로 하지 않은 이유: 한 판에 같은 이름이 둘 생기면 엔진의 대기 목록 `pendingNames`가 이름 기준 `Set<string>`이라 순위 패널의 대기 인원·"당첨" 강조가 틀어진다(같은 이름이 하나로 합쳐짐). 전체 초기화 후에는 어차피 1번부터 나가니 사용자가 체감하는 동작은 같다.
- 이전엔 `useRef` 카운터가 계속 올라가서, 초기화해도 게스트9~16으로 이어졌다. 그 카운터를 없앴다.

**DB 영향: 수정 불필요.** 확인한 것:
- 백엔드에 "게스트"라는 이름 의존 코드가 없다.
- `PlayerEntity.name`에 유니크 제약이 없고, 이름은 그냥 문자열(`@Size(max=20)`)이다.
- 빠른 추가 참가자는 `birthDate`가 null이라 `FortuneQueryService.getTodayFortune`이 이름 기준 캐시 조회를 하기 전에 바로 `NONE`으로 반환한다. 서로 다른 판의 "1번"끼리 캐시가 섞일 일이 없다.
- 기존 DB에 남아있는 "게스트N" 행은 그대로 둬도 무해하다.

## 3. 운세 확인 / 게임 시작 버튼을 제목 줄 오른쪽으로

- 섹션 제목과 버튼을 한 줄(`.panel-head`)에 두고, 설명 문구는 그 아래로 내렸다. 별도 `actions-row`는 없앴다(등록 폼의 "전체 초기화"와 관리자 화면에서는 계속 쓴다).
- 처음엔 좁은 화면에서 버튼이 제목 아래로 내려가게(`flex-wrap`) 했는데, 모바일(390px)에서 제목이 어절 중간(`곳/에서`)에서 끊기고 버튼이 제목과 설명 사이에 끼어 어색했다. 버튼은 같은 줄 오른쪽에 고정하고(`flex: 0 0 auto`), 제목이 `word-break: keep-all`로 어절 단위로 접히게 바꿨다.

## 검증

실제 브라우저(Playwright)로 데스크톱 1280×900, 모바일 390×844에서 확인했다.

| 항목 | 결과 |
|---|---|
| 빠른 추가 3명 → +2명 → 전체 초기화 후 4명 | 1~3번 → 4·5번 → 1~4번, 화면 어디에도 "게스트" 없음 |
| 제목 줄에 버튼 | 데스크톱·모바일 모두 같은 줄 오른쪽 |
| 8명 게임 종료 시 배너 | `.board-wrap` 안, 별도 결과 패널 없음, 보드 폭 안, **스크롤 없이 화면 안**, ✕ 닫기 동작, 페이지 오류 없음 |
| 모바일 보드 축소(`fitScale`) | 보드 폭 300px로 정상 축소, 배너가 보드 밖으로 안 넘침 |

**테스트하다 틈이 났던 것**: 처음엔 배너가 화면 밖으로 나왔다고 측정됐는데, 코드 문제가 아니라 테스트 문제였다. `page.click('게임 시작')`이 버튼을 보이게 하려고 페이지를 위로 되돌려 스크롤해서, 미리 맞춰둔 "보드 중앙을 보는 상태"가 풀린 것이다. 실제 사용자처럼 시작을 누른 **뒤에** 보드 중앙으로 스크롤하도록 고쳐서 측정했다.
