# 39. 참가자별 공 색 표시, 참가자 등록 버튼 스타일 통일

## 1. 참가자 등록 버튼을 AI TEST와 같은 스타일로

"참가자 등록" 버튼만 주황 강조(primary)였는데, 포트폴리오 시연에서는 AI TEST를 주로 누르므로 AI TEST와 같은 보조(secondary) 스타일로 맞췄다(`className="secondary"` 한 줄). 이제 이 줄에는 주황 강조 버튼이 없고, 주황은 2번 섹션의 "운세 확인"과 3번 섹션의 "게임 시작"에만 남는다. AI TEST를 주황으로 강조하는 쪽을 원하면 같은 한 줄로 바꿀 수 있다.

## 2. "누가 무슨 색 공인지" 표시

**문제**: 맵이 작아서 공 위의 이름을 읽기 어려운데, 어떤 참가자가 어떤 색 공인지 화면 어디에도 안 나와 있었다.

**원리**: 공 색은 게임 시작 때 **참가자 순서(= 등록 목록 순서)** 대로 배정된다(`palette[index]`, 백엔드가 `playerIds` 순서 그대로 참가자를 돌려준다). 그래서 같은 순서·같은 색을 게임 시작 **전**의 화면에도 미리 보여줄 수 있다.

**구현**
- 팔레트를 `game/ballColors.ts`로 빼서 엔진과 화면이 같은 값을 쓴다(`BALL_COLORS`, `ballColorAt(index)`). 색마다 한글 이름(회색·초록·하늘…)이 있어 점에 마우스를 올리면 "초록 공"처럼 보인다.
- 색 점을 세 군데에 붙였다: **등록 목록 칩**(빠른 추가·AI TEST·DB TEST 모두), **운세 카드 이름 앞**, **실시간 순위 패널**(진행 중·완주 모두).
- 등록 칩과 운세 카드는 React 컴포넌트(`BallDot`), 순위 패널은 엔진이 DOM을 직접 그리므로 같은 `.ball-dot` 클래스의 `<span>`을 만들어 붙인다. 순위 패널이 이름 기준 `Set`이던 것을 이름 → 색 `Map`으로 바꿔 색 정보를 같이 들고 다닌다(참가자 이름이 같으면 서로 덮어쓰는 기존 한계는 그대로다).
- 8번째 색을 **청록(`#22d3ee`) → 흰색(`#e5e7eb`)** 으로 바꿨다. 하늘(`#38bdf8`)과 청록은 작은 공에서 구분이 안 돼서, "하늘 공 / 청록 공"으로 표기해봐야 소용이 없기 때문이다. 흰색은 나머지 7색과 밝기부터 다르다.

**알아둘 점**: 참가자를 중간에 삭제하면 뒤 참가자의 색이 한 칸씩 당겨진다(순서 기준이라서). 게임 시작 때 실제 공 색도 그 시점의 순서로 정해지므로, 화면에 보이는 색과 공 색은 항상 일치한다.

## 검증

실제 브라우저(Playwright)에서 빠른 추가 8명 → **"2번" 삭제(색이 밀리는 경우)** → 운세 확인 → 게임 시작 → 완주까지 진행하면서, 이름 기준으로 색을 서로 대조했다.

| 항목 | 결과 |
|---|---|
| 참가자 등록 버튼 vs AI TEST 버튼 (배경·테두리·글자색·테두리 두께) | 동일 |
| 등록 칩 8개 색 = 팔레트 순서 | 일치 |
| 삭제 후 칩 색이 한 칸씩 당겨짐 | 일치 |
| 운세 카드 색 = 칩 색 | 일치 |
| 실시간 순위(진행 중) 색 = 칩 색 | 일치 |
| 실제 공(`.ball`) 배경색 = 칩 색 | 일치 |
| 실시간 순위(완주 후) 색 = 칩 색 | 일치 |
| 페이지 오류 | 없음 |

테스트 도중 순위 패널 두 항목이 처음엔 불일치로 나왔는데, 코드 문제가 아니라 테스트의 이름 추출 정규식이 원인이었다(순위 패널의 이름 앞 공백을 flex 간격으로 바꾸면서 `?3번`처럼 붙어 정규식이 이름을 통째로 잘라냄). 위치별로 `.position`·`.ball-dot`을 지운 뒤 이름을 읽도록 고쳐서 다시 확인했다.

레거시 `frontend/`에는 반영하지 않았다(화면 구성 변경은 React만, devhelp/25 기준).
