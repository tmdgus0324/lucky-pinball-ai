# 33. 평일 낮 시간대 슬립 방지 (GitHub Actions 핑)

Render 무료 티어는 일정 시간 요청이 없으면 인스턴스가 완전히 슬립 상태가 되고, 깨어나는 데 30~60초가 걸린다. 면접·시연 시간대에 이 지연을 없애기 위해, **정해진 시간대에만** 주기적으로 서버를 깨워두는 워크플로우를 추가했다.

## 왜 24시간 내내 안 켜두는가

Render 무료 티어는 계정당 월 가동시간 한도가 있다(대략 750시간/월로 알려져 있음 — 정확한 최신 수치는 Render 대시보드에서 확인 필요). 24시간 내내 깨워두면 한 달 내내 켜진 것과 같아서 이 한도에 훨씬 빨리 가까워진다.

계산:
- 처음엔 10시~17시로 검토했다가, 이후 **9시 시작 + 주말 제외**로 조정했다.
- 평일 9시~17시(하루 9시간) × 약 22일(주말 제외) = **약 200시간/월** — 한도 대비 여유 있음
- 주말은 면접·시연이 있을 확률이 낮아서 아예 제외했다.
- 점심시간(11:30~13:00)을 빼고 더 쪼개는 것도 검토했지만, 아껴지는 시간에 비해 cron 규칙이 두 개로 늘어나는 복잡함이 더 커서 단순한 연속 구간으로 결정했다.

## 왜 UptimeRobot 같은 외부 서비스 대신 GitHub Actions인가

- **새 계정이 필요 없다** — 이미 CI에 쓰고 있는 GitHub Actions 그대로 재사용.
- **시간대 제한이 가능하다** — UptimeRobot 같은 업타임 모니터링 서비스의 무료 플랜은 보통 "항상 몇 분 간격으로" 방식이라 "낮 시간에만" 같은 스케줄 제한이 어렵다. GitHub Actions의 `schedule`(cron)은 시간대를 그대로 지정할 수 있다.
- **완전 무료** — public 저장소는 GitHub Actions 실행 시간이 무제한이라 별도 비용이 없다.

## 구성

```yaml
on:
  schedule:
    # 10분마다, UTC 00:00~08:59(한국시간 09:00~17:59) · 요일 1~5(월~금)
    - cron: '*/10 0-8 * * 1-5'
  workflow_dispatch:

jobs:
  ping:
    runs-on: ubuntu-latest
    steps:
      - name: Ping backend
        run: curl -sf --max-time 60 https://lucky-pinball-backend.onrender.com/api/players/reusable || true
```

- **cron은 UTC 기준**이라 한국시간(KST, UTC+9)으로 환산해서 넣어야 한다 — 9~17시(KST) = 00~08시(UTC).
- **요일도 UTC 기준**이지만, 이 핑 시간대(UTC 00:00~08:59)는 날짜가 안 바뀌는 구간이라 UTC 요일과 한국 요일이 동일하다 — 그래서 `1-5`(월~금)를 그대로 써도 된다. 만약 시간대가 자정을 걸쳐 있었다면 요일이 하루씩 밀리는 걸 감안해야 했을 것.
- 핑 대상은 `/api/players/reusable` — 로그인 없이 항상 200을 반환하는 공개 엔드포인트(DB TEST용으로 이미 만들어둔 것, devhelp/32)라 별도 인증 처리 없이 그냥 호출하면 된다.
- `workflow_dispatch`를 같이 넣어서, 스케줄과 무관하게 필요할 때 수동으로도 즉시 실행해볼 수 있게 했다.
- GitHub Actions의 스케줄 실행은 부하 상황에 따라 몇 분 정도 오차가 날 수 있다는 점은 감안해야 한다(공식 문서에 명시된 제약).

## 검증

`workflow_dispatch`로 수동 실행해서 실제로 백엔드에 핑이 가고 응답을 받는지 확인.
